# 跨 Part 候选面视觉邻接语义规范

## 目的

规定两个不同 Part 的候选 PathNode，在固定游戏相机下何时可以形成**视觉邻接**。这里比较的是两个候选节点所附着的可走面及其道路边，不是节点中心点之间的距离。

本规范只定义跨 Part 的视觉候选评估，不定义同一 Part 内的真实面邻接。两者分别遵守：

- 同一 Part：`docs/tri-prism-face-adjacency-spec.md`
- 跨 Part：本规范

## 落地状态

稳定几何判定已闭环：先检查两个附着面在固定游戏相机下的投影边是否有正长度线段重合。重合成功后，再沿重合接缝做逻辑体素面遮挡评估。深度差、端点间隙和“道路连续”仍不得替代边重合。缺少遮挡证据时记为 `insufficient-evidence`，不得自动通过。

## 核心语义

```text
两个候选节点所附着的可走面
  -> 应用各自 Part 当前 Transform
  -> 使用固定游戏相机投影到屏幕空间
  -> 对应面边发生正长度线段重合
  -> 重合接缝未被更近的逻辑体素面切断
  -> 生成视觉有效边
```

跨 Part 视觉邻接是：

```text
真实空间中的面不必共面或相接
  + 固定相机投影下道路边看起来连续
  -> 允许形成视觉邻接
```

## 必要条件

两个候选面的视觉邻接必须满足：

1. 两个候选节点都存在且 `walkable == true`；
2. 两个节点所附着的面属于允许的可走面语义；
3. 两个面的道路边能够根据附着面的几何直接确定；
4. 面和道路边经过各自 Part 当前 Transform 后，能够得到世界空间顶点、法线和边；
5. 使用固定游戏相机投影后，两条对应面边存在正长度线段重合；
6. 两个 Part 当前处于允许参与评估的合法机关 Snap 状态；
7. 重合接缝上的采样视线没有被比两端附着面更近的逻辑体素面切断。

“道路连续”、端点间隙和节点中心距离仍不是接受条件。缺少遮挡证据时不得当作通过。

## 面和道路边的投影连续性

跨 Part 评估比较的是面边，不是面中心：

```text
面一的出口道路边
  -> 固定相机投影
面二的入口道路边
  -> 固定相机投影
```

投影后的两条边必须满足：

- 共线；
- 交集长度大于零。

方向相似只是共线检查的数学前置，本身不构成连接。

仅有以下情况时，不得建立视觉边：

- 两个面中心投影接近，但道路边不连续；
- 两个节点投影重合，但入口/出口方向不兼容；
- 两条投影边只有一个端点接触；
- 两个面投影完全重叠但深度和遮挡关系无法解释。

## 法线和深度语义

跨 Part 不要求两个面在真实世界中共面，也不要求真实法线相同。

评估使用：

- 世界空间面法线：判断面是否具有合理的可走朝向；
- 屏幕空间道路边方向：判断视觉行走方向是否连续；
- 固定相机视图深度：判断前后遮挡关系是否可解释。

```text
真实法线不同并不自动拒绝
真实面不共面并不自动拒绝
投影方向、深度和遮挡不成立才拒绝
```

## 遮挡语义

遮挡判断服务于视觉接缝连续性，不是物理碰撞寻路，也不是“相机看不见节点中心”。

评估对象是投影重合后的屏幕空间 `overlapSegment`，不是两端锚点连线，也不是角色世界空间轨迹。

第一版规则：

```text
投影边正长度重合
  -> 取 overlapSegment
  -> 沿接缝采 3 点，并向两端面投影中心微内缩
  -> 每点用固定游戏相机 GetScreenRay
  -> 对所有 Part 局部体素面做逻辑面射线
  -> 忽略两端附着面、同 Cell 面、共面支撑面
  -> 比两端附着面都更靠近相机的逻辑面视为 occluder
```

明确忽略：

- 物理碰撞 / Mesh / Octree 三角形射线；
- 编辑器自由相机；
- 角色、Gizmo、Overlay、地板盒；
- 接缝后面或三维中切开两端的几何，那是错视间隙，不是遮挡；
- 机关动画中的半旋转姿态。

结果：

```text
occluder            -> rejected: visual-seam-occluded
采样打不到两端面    -> insufficient-evidence
无更近切断面        -> accepted
```

`insufficient-evidence` 不进入 `CurrentEffectiveGraph`。不得把缺少遮挡证据误认为自动通过。

## 候选与有效边的区别

```text
pathCandidate
  -> 设计者允许这两个 Part 面进入评估范围

visual evaluation
  -> 当前 Snap 状态和固定相机下检查两面投影关系

accepted visual edge
  -> 评估通过后进入 CurrentEffectiveGraph
```

候选本身不表示已经连通，也不保存运行时屏幕坐标、深度或评估结果。

## 与 Part 内面邻接的区别

```text
同一 Part：
  面真实共面
  + 边有正长度重合
  + 同向法线
  -> 局部固定边

跨 Part：
  真实面可以不共面、不相接
  + 固定相机下投影面边正长度重合
  -> 视觉有效边
```

跨 Part 视觉邻接可以理解为：

> 将 Part 内的“面/边连续性”思想应用到固定相机的视觉空间，但不复制真实空间的共面条件。

## 运行时更新边界

```text
机关动画中
  -> 只更新表现层
  -> 不提交新的视觉有效边

机关到达合法 Snap 状态
  -> 重新获取两个候选面的世界几何
  -> 重新投影面边
  -> 按正长度线段重合重新评估
  -> 原子替换当前有效视觉边
```

视觉有效边必须由 `PathRuntime` 的派生结果提供给寻路；BFS 不参与视觉评估，也不修改 Graph。

## 稳定版唯一几何判定

跨 Part 视觉邻接的唯一几何核心是：

```text
两个候选节点所附着的面
  -> 应用各自 Part Transform
  -> 投影到固定 Runtime/Game 相机的 2D 空间
  -> 对应的面边发生正长度线段重合
  -> 重合接缝未被更近逻辑面切断
  -> accepted visual edge
```

这里的“边重合”是严格的线段重合：两条投影线段必须共线，并且交集长度大于零。只有端点接触不算重合。

面类型对应：

```text
top / bottom 三角面
  -> 投影三角形边与投影三角形边进行正长度重合检测

side_1 / side_2 / side_3 矩形面
  -> 投影侧面竖边与投影侧面竖边进行正长度重合检测
```

## 明确禁止的替代语义

以下概念不得替代“投影面边正长度重合”：

- 道路边连续；
- 首尾连接；
- 端点间隙小于阈值；
- 节点中心投影接近；
- 投影边方向相似但没有线段交集；
- 世界空间距离接近；
- 相机深度差接近。

方向相似可以作为共线的数学前置检查，但**方向相似本身不构成连接**。端点间隙也不构成连接。

项目代码和文档的稳定版术语统一使用“投影面边正长度线段重合”，不使用“道路边连续”或“端点间隙”作为判定名称。

实现必须对两个附着面的合法边集合进行两两检查，不能为每个面预先选出一条“道路边”。任意一对投影边满足正长度线段重合即可接受，并记录匹配的边索引。
