# 跨 Part 候选面视觉邻接语义规范

## 目的

规定两个不同 Part 的候选 PathNode，在固定游戏相机下何时可以形成**视觉邻接**。这里比较的是两个候选节点所附着的可走面及其道路边，不是节点中心点之间的距离。

本规范只定义跨 Part 的视觉候选评估，不定义同一 Part 内的真实面邻接。两者分别遵守：

- 同一 Part：`docs/tri-prism-face-adjacency-spec.md`
- 跨 Part：本规范

## 核心语义

```text
两个候选节点所附着的可走面
  -> 应用各自 Part 当前 Transform
  -> 使用固定游戏相机投影到屏幕空间
  -> 比较投影后的道路边连续性
  -> 检查投影方向、深度和遮挡
  -> 生成视觉有效边
```

跨 Part 视觉邻接是：

```text
真实空间中的面不必共面或相接
  + 固定相机投影下道路边看起来连续
  -> 允许形成视觉邻接
```

## 必要条件

两个候选面的视觉邻接必须满足：

1. 两个候选节点都存在且 `walkable == true`；
2. 两个节点所附着的面属于允许的可走面语义；
3. 两个面的入口边和出口边能够根据节点的 `entryDirection`、`exitDirection`、`orientation` 确定；
4. 面和道路边经过各自 Part 当前 Transform 后，能够得到世界空间顶点、法线和边；
5. 使用固定游戏相机投影后，两条道路边满足屏幕空间连续性；
6. 投影后的行走方向兼容；
7. 两个面的相机深度关系在允许范围内；
8. 中间没有会破坏视觉连续性的遮挡；
9. 两个 Part 当前处于允许参与评估的合法机关 Snap 状态。

## 面和道路边的投影连续性

跨 Part 评估比较的是面边，不是面中心：

```text
面一的出口道路边
  -> 固定相机投影
面二的入口道路边
  -> 固定相机投影
```

投影后的两条边至少应满足：

- 方向连续或处于允许角度容差内；
- 端点间隙小于屏幕空间容差，或线段存在足够长度的重合；
- 投影边不发生明显反向折断；
- 面的可走区域投影具有连续的进入/离开关系。

仅有以下情况时，不得建立视觉边：

- 两个面中心投影接近，但道路边不连续；
- 两个节点投影重合，但入口/出口方向不兼容；
- 两条投影边只有一个端点接触；
- 两个面投影完全重叠但深度和遮挡关系无法解释。

## 法线和深度语义

跨 Part 不要求两个面在真实世界中共面，也不要求真实法线相同。

评估使用：

- 世界空间面法线：判断面是否具有合理的可走朝向；
- 屏幕空间道路边方向：判断视觉行走方向是否连续；
- 固定相机视图深度：判断前后遮挡关系是否可解释。

```text
真实法线不同并不自动拒绝
真实面不共面并不自动拒绝
投影方向、深度和遮挡不成立才拒绝
```

## 遮挡语义

遮挡判断服务于视觉连续性，不是物理碰撞寻路：

- 不使用物理碰撞自动创建边；
- 不使用 Mesh 距离自动创建边；
- 不使用编辑器自由相机评估；
- 只检查固定游戏相机下是否有几何体遮断候选道路的投影连续性。

如果当前评估器还没有可靠的遮挡数据，候选应记录为：

```text
pending / insufficient-evidence
```

而不是把缺少遮挡检查误认为自动通过。

## 候选与有效边的区别

```text
pathCandidate
  -> 设计者允许这两个 Part 面进入评估范围

visual evaluation
  -> 当前 Snap 状态和固定相机下检查两面投影关系

accepted visual edge
  -> 评估通过后进入 CurrentEffectiveGraph
```

候选本身不表示已经连通，也不保存运行时屏幕坐标、深度或评估结果。

## 与 Part 内面邻接的区别

```text
同一 Part：
  面真实共面
  + 边有正长度重合
  + 同向法线
  -> 局部固定边

跨 Part：
  真实面可以不共面、不相接
  + 固定相机下投影道路边连续
  + 方向、深度、遮挡成立
  -> 视觉有效边
```

跨 Part 视觉邻接可以理解为：

> 将 Part 内的“面/边连续性”思想应用到固定相机的视觉空间，但不复制真实空间的共面条件。

## 运行时更新边界

```text
机关动画中
  -> 只更新表现层
  -> 不提交新的视觉有效边

机关到达合法 Snap 状态
  -> 重新获取两个候选面的世界几何
  -> 重新投影道路边
  -> 重新评估方向、深度和遮挡
  -> 原子替换当前有效视觉边
```

视觉有效边必须由 `PathRuntime` 的派生结果提供给寻路；BFS 不参与视觉评估，也不修改 Graph。

## 当前实现状态

跨 Part 原型现在已开始比较候选面道路边的投影数据，并记录投影边方向和端点间隙。遮挡仍未接入可靠评估，因此当前结果仍属于不稳定原型；未检查遮挡不能解释为遮挡通过。

因此当前实现属于不稳定原型，不能将节点中心投影阈值视为本规范的最终实现。
