# 六边形纪念碑谷：剧情级 Standalone 3D 模型调研与 P0 资产方案

## 文档定位

本文承接 `docs/hexagonal-monument-valley-art-direction-research.md`，专门回答一个问题：

> 在三棱柱体素作为核心玩法结构的前提下，哪些 standalone 3D 模型具有剧情级 P0 价值，值得优先制作？

本文不建议把所有建筑替换成普通 Mesh，也不建议继续让所有剧情物件都由体素拼成。目标是建立清晰的混合边界：

```text
三棱柱体素负责可改变的空间逻辑
模块化 3D Mesh 负责固定建筑轮廓
Standalone 3D 模型负责剧情记忆；可动 Part 的机关身份由 hover emission 承担，不再做枢轴/六向环
```

本文中的 P0 指：

- 在当前剧情策划中有明确用途；
- 能跨章节反复出现，或虽低频但不可替代；
- 玩家能形成视觉记忆；
- 用单纯三棱柱体素难以表达其身份；
- 不依赖大规模环境资产包即可验证。

P0 不是“最常见的环境模型”，也不是“制作成本最低的模型”。

---

## 一、核心结论

### 1. 全部使用体素的问题

当前项目的建筑主要由 `VoxelRenderer` 生成三棱柱体素，再由 `PartRootRenderer` 负责 Part 组装和旋转。这对玩法白盒是正确的，但如果建筑、机关、门、窗、实验设备、花束和墓碑都继续使用同一种体素语法，会产生四个问题：

1. 建筑、机关和叙事物件没有视觉层级；
2. 门、阿尔吉侬、花等剧情对象难以形成独立记忆；
3. 远景塔和高处空间的轮廓会被小体素重复稀释；
4. 各章节只能依赖换色表达变化，世界缺乏身份和历史。

这里的问题不是体素形式本身不好，而是体素被迫承担了过多不同职责。

### 2. 不建议把正式关卡全部替换成普通 3D

Path Graph 当前依赖：

```text
VoxelDocument.pathNodes
  + Part 的离散 Transform / Snap 状态
  + 固定游戏相机
  + 视觉边连接评估
  -> PathRuntime 当前有效 Graph
```

可走面、台阶、桥和可移动结构仍然需要保留在体素/逻辑结构中。普通 Mesh 不应该反向定义 Path Graph，也不应该成为角色寻路的隐式数据源。

因此不建议采用：

```text
体素只用于原型
  -> 正式版全部换成普通 Mesh
```

这会损害错视玩法的可解释性，并重新制造逻辑 Graph、视觉连接和表现层之间的耦合。

### 3. 推荐的四层资产结构

```text
A. 玩法结构层：三棱柱体素
B. 建筑语言层：模块化非体素 3D Mesh
C. 交互语义层：特定 3D 机关与功能物件
D. 叙事焦点层：角色、动物、花、墓碑等独立资产
```

#### A 层：继续使用三棱柱体素

负责：

- 可走面；
- 平台；
- 台阶；
- 墙；
- 桥；
- 中央旋转结构；
- 可移动 Part；
- 参与视觉连接评估的边和面。

#### B 层：模块化建筑 Mesh

负责：

- 门框外壳；
- 固定窗框；
- 拱门；
- 屋檐；
- 观察台外壳；
- 远景塔顶；
- 固定护栏；
- 花园石墙；
- 远景建筑剪影。

这些模型不拥有路径节点，不参与寻路，只负责让体素建筑拥有建筑身份和远景轮廓。

#### C 层：机关和功能物件

可动 Part（Rotator / Mover）的机关身份不走独立枢轴模型，而走体素 look 的 hover emission：悬停且此刻能拖才亮，走路锁住不亮，0.5 秒可打断 fade。独立 3D 仍负责：

- 门扇状态；
- 观察窗；
- 研究记录台；
- 章节状态反馈对象。

#### D 层：叙事焦点

负责：

- 查理；
- 阿尔吉侬；
- 花束；
- 阿尔吉侬纪念石座/墓；
- 必要的远景角色剪影。

这些对象需要有独立轮廓、独立材质状态和明确的剧情复用。

## 二、P0 的筛选标准

一个 standalone 3D 模型只有同时满足以下条件，才应进入 P0：

### 条件 A：剧情中有重复或不可替代的动作

例如：

- 进入、离开、关闭、打开；
- 观察、记录、被观察；
- 先行、停留、失效；
- 纪念、放花、抵达。

### 条件 B：体素难以提供稳定身份

如果一个对象只需要表达“这里有一块墙”，应该继续用体素。

如果玩家必须认出：

```text
这是门
这是阿尔吉侬
这是观察装置
这是墓
这是花
```

那么它更适合成为独立模型。

### 条件 C：模型不应侵入玩法真相

默认 standalone 资产：

- 不拥有 PathNode；
- 不生成 Path Graph 边；
- 不改变 BFS；
- 不定义角色可达性；
- 不替代 Part 的旋转状态；
- 不遮挡视觉连接候选边。

### 条件 D：能在固定正交相机下形成清晰剪影

不是建模精度越高越好。P0 模型首先需要：

- 小屏幕下可认出；
- 远处缩小后仍有轮廓；
- 与三棱柱体素保持材质语言一致；
- 不靠高频纹理识别；
- 不依赖自由镜头展示细节。

## 四、P0-1：DoorKit

### 1. 门的剧情价值

门是当前项目最应该优先制作的 standalone 资产。

在当前剧情中，门不只是目标标记，而是反复承担：

```text
门 = 目的地
门 = 章节转场
门 = 世界状态变化的证据
```

剧情中的关键应用包括：

- 第一章结束：一扇亮起的门将查理和阿尔吉侬带入研究所；
- 第二章：研究所打开，门成为新区域入口；
- 第三章：高处房间、观测区域和研究所内部；
- 第四章：研究所重新封闭，熟悉的门不再打开；
- 第五章：进入花园和墓地的低矮入口。

### 2. 模型组成

#### `NarrativeDoor_Frame`

独立门框，作为跨章节反复出现的视觉母题。

建议形态：

- 高而窄的几何门框；
- 两侧略带倾斜或三角切面；
- 顶部不做复杂拱顶；
- 轮廓在远景中可辨；
- 尺寸与三棱柱网格对齐，但不必由体素拼成。

#### `NarrativeDoor_Leaf`

门扇或门洞内部的表现模型。

建议支持状态：

```text
closed      关闭
open        打开
lit         亮起
 dim        暗下
sealed      封闭但仍可见
```

不建议每个状态都制作独立模型文件。状态优先由以下方式组合：

- 节点启用/隐藏；
- 门扇旋转或滑动；
- 材质颜色；
- Emissive；
- 简短、非循环的状态动画。

### 3. 五章应用

| 章节 | 门状态 | 叙事功能 |
|---|---|---|
| 第一章 | 暗门变为暖光门 | 第一次进入实验世界 |
| 第二章 | 青瓷门、多个开放门 | 世界正在打开 |
| 第三章 | 冷白观测门 | 进入高处和被观察的空间 |
| 第四章 | 熟悉的门变暗或无法打开 | 旧道路和旧世界失效 |
| 第五章 | 简单低矮花园入口 | 从复杂建筑回到真实道路 |

### 4. 玩法边界

门不能直接拥有 PathNode，也不能直接生成 Path Graph 边。

推荐结构：

```text
体素可走面 / 门洞路径 = PathNode 和 Graph 的真相
门框 / 门扇 = 表现层
门的开关状态 = 关卡状态或叙事状态
```

门框不能遮挡视觉连接候选边。门应该强化“路通向哪里”，而不是让玩家看不清道路是否连接。

### 5. 为什么门排第一

门具有其他资产没有的优势：

- 五章都能合理出现；
- 既能做目标，又能做转场；
- 能表现打开和封闭；
- 能低成本复用多个状态；
- 能承载章节余波；
- 玩家会在不同状态下认出“还是那扇门”。

## 五、P0-2：Charlie

> **制作状态：暂缓。** 查理已纳入剧情级 P0 计划，但当前不进入正式建模和导入流程。设计方向、比例和动作规范仅作为灵感与约束，具体造型由项目方自行建模并逐步收敛。当前生成的角色原画只作为探索参考，不是最终模型定稿。

### 1. 角色定位

查理是唯一的主操作角色，也是玩家观察空间、理解路径和执行最终纪念动作的视觉参照。它不能被制作成一个具象化的普通人，也不能退化成没有身份的抽象几何符号。

目标不是“隐藏查理是什么人”，而是把人物信息压缩到固定正交相机最需要的几个信号：

```text
人形姿态
  + 无脸
  + 稳定服装/色块
  + 清晰头身比例
  + 可读的手脚和朝向
```

查理应该被玩家认出是“一个人”，但不应被要求认出具体年龄、脸部、发型、职业或现实身份。

### 2. `Charlie_Silhouette` 的具体形态

建议制作成**无脸的几何旅人**，参考纪念碑谷角色“远景先读轮廓、近景再读姿态”的方法，但不复制任何具体角色：

- 独立头部，略小于真实人体比例；
- 简化躯干，接近短斗篷、长外套或连体衣的整体轮廓；
- 两条短而清楚的腿，脚部略向外分开；
- 两条极简手臂，至少能看出垂落、等待和行走；
- 无眼睛、鼻子、嘴和耳朵；
- 不做具体发型，可用非常短的头顶轮廓表示头部方向；
- 不做写实手指、衣物褶皱和布料物理；
- 轮廓应比当前胶囊更像“人”，但比完整人物更像一个符号。

推荐轮廓比例：

```text
总高：1.00
头部：0.20～0.24
躯干：0.38～0.44
腿部：0.28～0.34
肩宽：总高的 0.24～0.30
```

这是屏幕识别比例，不是现实人体解剖比例。固定正交视角下，头、躯干、腿和脚的分离比真实比例更重要。

### 3. 推荐的建模形态

第一版建议使用 3～5 个独立子网格或骨骼部件：

```text
Head
Torso / Coat
Arm_L + Arm_R
Leg_L + Leg_R
```

如果需要减少资源复杂度，可以将两臂合并、两腿合并，但不要把头和躯干合并成一个无关节胶囊。

形体方向：

- 头部：低面数圆角体或略带切面的球体；
- 躯干：向下略收窄的短斗篷/外套体；
- 手臂：细短的圆角棱柱；
- 腿：两条短直腿或略微弯曲的低面数体块；
- 鞋：不必单独建模，可用腿底部的深色小切面表示。

不要加入：

- 五官；
- 写实头发；
- 具体制服徽章；
- 实验病患服；
- 真实职业道具；
- 复杂衣褶；
- 夸张披风；
- 让玩家误认成另一种动物的尖耳或尾巴。

### 4. 为什么选择“无脸旅人”

脸部会把玩家注意力从空间转向角色身份，也会迫使美术做出年龄、种族、表情和现实背景的判断。当前剧情并不需要这些信息。

完全抽象的球、胶囊或单个三棱柱又会削弱：

- 玩家对查理的角色认知；
- 角色走路、等待和回头的叙事信息；
- 结尾“查理放下花”的动作可读性。

“无脸旅人”处于两者之间：

```text
远景：读作一个人
中景：读作查理
近景：仍然不提供具象身份
```

### 5. 色彩和材质

查理需要成为跨章节的稳定视觉锚点，模型本身不随章节换造型。

建议使用两个主要材质槽：

```text
Body / Coat：暖黄或浅赭色
Head / Skin：略偏暖的浅肤色或统一浅暖色
```

候选颜色：

```text
身体：#D9AD55 ～ #E0B85E
头部：#E7B38A 或 #E7C08B
```

如果希望进一步抽象，可以让头部和身体使用相近色，但必须保留明度差，避免头部和躯干粘成一块。

材质建议：

- 优先 Unlit 或受控 Surface Shader；
- 保持稳定的纯色轮廓；
- 不使用皮肤纹理；
- 不使用衣物纹理；
- 不使用明显金属；
- 不用强高光改变角色轮廓；
- 角色不跟随章节整体饱和度完全褪色，始终略暖于环境。

### 6. 姿态和动画需求

第一版只需要表达剧情必需的动作：

```text
idle       站立，略有呼吸或轻微重心变化
walk       腿部交替，步幅短而稳定
turn       整体转向，不做复杂扭腰
wait       面向远处目标或门
place      放下花束时短暂弯腰/伸手
```

不需要：

- 战斗动作；
- 跑步；
- 跳跃；
- 攀爬；
- 复杂面部表情；
- 物理布料。

角色动画应服务于路径和叙事节奏，不能抢过建筑空间。

### 7. 与阿尔吉侬的区分

查理和阿尔吉侬都采用简化轮廓，但识别信号必须不同：

| 对象 | 主要轮廓 | 主要颜色 | 叙事含义 |
|---|---|---|---|
| 查理 | 直立人形、头/躯干/双腿 | 暖黄、浅赭 | 玩家行动、理解和选择 |
| 阿尔吉侬 | 低矮侧卧动物、耳朵/鼻尖/尾巴 | 浅白 | 先行者、对照和被记住的生命 |

阿尔吉侬当前模型图的方向是对的：轮廓清楚、低面数、没有写实毛发。建模时只需确保尾巴和后腿在固定相机的小尺寸下仍可辨，不需要继续增加脸部或身体细节。

### 8. 玩法边界

```text
Charlie_Silhouette = 角色表现
PlayerController = 位置、路径和移动逻辑
PathRuntime = 当前有效 Graph
```

查理模型：

- 不拥有 PathNode；
- 不生成 Graph 边；
- 不参与视觉连接评估；
- 不通过碰撞体反向定义可达性；
- 可以在 Overlay 中置顶显示，但颜色和主场景应保持一致；
- 放花动作发生在抵达纪念石座之后，不改变 Path Graph。

## 六、P0-3：Algernon

### 1. 阿尔吉侬的剧情价值

阿尔吉侬不是普通 NPC，也不是剧情开关，而是玩家观察到的生命对照。

当前剧情中它会：

- 先走过查理走不过的路；
- 在远处作为移动白点或小型角色出现；
- 经历和查理相关的实验；
- 停在曾经可走的位置；
- 最终成为花园和墓地的情感核心。

它必须拥有独立轮廓，不能永远用普通白点或体素替代。

### 2. `Algernon_Silhouette`

第一版不追求写实老鼠模型，建议：

- 极简白色小鼠；
- 清楚的小耳朵；
- 小鼻尖；
- 短尾巴；
- 简化身体；
- 固定正交相机下轮廓柔和但可辨；
- 缩小到远景后仍像小动物。

建议先支持：

```text
idle
walk
stop
turn
```

如果动画系统尚未准备好，第一版可以使用节点位置、朝向和轻微上下浮动表现。

### 3. 材质状态

同一模型支持多个材质或颜色状态：

```text
normal      明亮白色
active      白色略带暖光
distant     低对比度浅灰白
weak        低饱和、略暗
resting     几乎静止的浅白
```

不要使用：

- 生病特效；
- 抽搐；
- 破碎；
- 血液；
- 恐怖变形；
- 夸张死亡动画。

剧情重点是“它停止走通旧路”，不是把它做成恐怖对象。

### 4. 为什么胶囊不能长期代替

查理可以暂时是胶囊，因为他代表玩家行动，重点是位置、方向和移动。

阿尔吉侬需要一点独立轮廓，因为它代表玩家观察到的生命：

```text
查理 = 玩家行动
阿尔吉侬 = 玩家观察到的生命
```

## 七、P0-4：ObservationKit

ObservationKit 建议包含两个模型：

- `Observation_Console`
- `Observation_Window`

### 1. 叙事价值

当前剧情中反复出现：

- 研究所；
- 观察；
- 研究人员；
- 实验；
- 阿尔吉侬的记录；
- 研究结果；
- 查理被当作成果观察。

如果没有一个反复出现的观察/记录物件，玩家只能依赖文本理解“这里有人在看”。

### 2. `Observation_Console`

建议形态：

- 矮台；
- 倾斜平面；
- 一条竖向观察窗或光带；
- 极少量几何按钮或指示灯；
- 不做现实电脑；
- 不显示可读文字；
- 不做科幻霓虹 UI。

适合出现于：

- 第二章研究室；
- 第三章旁观席；
- 第三章阿尔吉侬的记录；
- 第四章空房间；
- 章节之间的转场空间。

叙事功能：

```text
有人在看
有人在记录
这个空间不是自然形成的
```

### 3. `Observation_Window`

建议形态：

- 细长竖向窗；
- 简化窗框；
- 冷蓝透明片；
- 低强度发光内缘；
- 远处缩小后仍能形成识别符号。

它可以表达：

- 查理站在高处；
- 研究人员从远处看他；
- 查理看见下方世界却无法抵达；
- 阿尔吉侬在另一侧；
- 第四章窗户逐渐熄灭。

### 4. 透明材质边界

玻璃应该是章节语义资产，而不是全场景默认材质。

透明模型必须单独验证：

- 深度顺序；
- 可走面的可读性；
- 视觉候选边是否被错误遮挡；
- Overlay 和主场景的颜色一致性。

---

## 八、可动机关身份：Hover Emission（替代 SixWayAxis）

Rotator 和 Mover 共用同一套体素反馈，不再制作独立枢轴或六向环。枢轴会破坏“建筑自己在动”的氛围，也无法同时覆盖平移。

```text
亮 = 鼠标悬停该 Part 且此刻确实能拖
走路锁住（角色正在该 Part 上走）= 不亮
上升沿 / 下降沿 = 0.5 秒可打断 fade
颜色 / 强度写入 Part.look.emissionColor / emissionStrength
默认颜色 #FFF4D2，默认强度 0.25
```

静止时几乎看不出机关。发光不能等价于道路成立；道路仍由 PathRuntime 评估。

---

## 九、P0-5/P0-6：MemorialStone 与 FlowerBouquet

这组资产的使用频率不一定高，但剧情权重是 P0，因为它们承担故事的最终记忆和情绪收束。

### 1. `Algernon_Memorial`

建议不要制作现实墓园中的复杂墓碑，而是制作一个和建筑语言一致的纪念石座：

- 低矮石座；
- 简化小型纪念碑；
- 柔和切角；
- 不放大段文字；
- 不做十字架等现实墓园符号；
- 和三棱柱建筑保持几何关系。

它可以在第四章后段远远出现，到了第五章才真正抵达：

```text
远处可见
  -> 曾经到不了
  -> 旧连接逐步失效
  -> 最终沿真实道路抵达
```

这比结尾才突然生成墓碑更有叙事力量。

### 2. `Flower_Bouquet`

建议做一束花，而不是一片花田：

- 3～5 朵花；
- 细茎；
- 2～3 片叶子；
- 简化花瓣轮廓；
- 可以有轻微随风摆动；
- 全游戏最高饱和度颜色；
- 不使用花瓣爆散粒子；
- 不做奖励道具形态。

前四章可以让花色作为极少量远处预兆，但真正的花束直到第五章才实体出现。

### 3. 玩法边界

纪念石座和花束都是表现/叙事对象：

- 不拥有 PathNode；
- 不定义墓地可达性；
- 不参与 BFS；
- 终点节点仍由关卡配置和 Path Graph 决定；
- 放花是抵达后的叙事状态变化。

## 九、按章节的 P0 应用

### 第一章：愿望 / 跑不过的迷宫

使用：

- DoorKit；
- 体素 Part 的 hover emission 机关反馈；
- 查理；
- 阿尔吉侬；
- 极少量门光。

表现重点：

```text
真实道路
  -> 旋转机关
  -> 第一次错视连接
  -> 门亮起
```

不需要完整面包店模型。第一章先用门、窗光和低处建筑轮廓表达生活背景即可。

### 第二章：实验 / 打开的世界

使用：

- DoorKit；
- 体素 Part 的 hover emission 机关反馈；
- 查理；
- 阿尔吉侬；
- Observation_Window；
- （P0.5）Observation_Console。

表现重点：

- 观察台反复出现；
- 青瓷门逐渐打开；
- 观察窗和远景塔让空间变高；
- 阿尔吉侬走过一条查理暂时走不过的路。

### 第三章：高峰 / 高处没有朋友

使用：

- DoorKit；
- 体素 Part 的 hover emission 机关反馈；
- 查理；
- Observation_Window；
- （P0.5）Observation_Console；
- 阿尔吉侬。

表现重点：

- 高塔和观察窗建立“被观察”的世界；
- 阿尔吉侬的记录可以通过 Observation Console 表达；
- 门仍然明亮，但空间开始空旷；
- 阿尔吉侬停在曾经成立的路径上。

### 第四章：衰退 / 道路正在消失

使用：

- DoorKit 的暗化状态；
- 体素 Part 的 hover emission 机关反馈；
- 查理；
- Observation_Window；
- （P0.5）Observation_Console；
- 阿尔吉侬；
- 远处出现 Algernon_Memorial。

表现重点：

- 复用过去的建筑和门；
- 不增加恐怖装饰；
- 不降低玩家操作能力；
- 通过旧门关闭、窗口熄灭和视觉连接减少表达世界变化。

### 第五章：纪念 / 给阿尔吉侬的花

使用：

- Algernon_Memorial；
- Flower_Bouquet；
- 简化 DoorKit 作为花园入口；
- 不再使用复杂的可动机关。

表现重点：

- 回到低处和真实道路；
- 角色抵达纪念石座；
- 查理放下花；
- 建筑不再发生大型变化；
- 花束成为画面唯一高饱和焦点。

## 十、制作与技术规范

### 1. 生产形式

正式 P0 可以组织成 6 个资源包，另有一个 P0.5 资源包：

```text
DoorKit
  - NarrativeDoor_Frame
  - NarrativeDoor_Leaf
  - closed/open/lit/dim/sealed 状态

Charlie
  - Charlie_Silhouette
  - idle/walk/turn/wait/place 状态

Algernon
  - Algernon_Silhouette
  - normal/distant/weak/resting 状态

ObservationWindow
  - Observation_Window

ObservationConsole（P0.5）
  - Observation_Console

MemorialStone
  - Algernon_Memorial

FlowerBouquet
  - Flower_Bouquet
```

### 2. 尺寸规范

以当前三棱柱边长 `1m` 为网格参考：

```text
小物件：0.25m～0.75m
阿尔吉侬：约 0.25m～0.45m 的简化比例
门框：宽 1m～2m，高 1.5m～3m
观察窗：宽 1m～3m
枢轴：直径约 1m～2m
纪念石座：宽 1m～2m，高 0.5m～1.5m
花束：约 0.25m～0.6m
```

实际导入尺寸需要通过模型 boundingBox 和固定相机截图校准，不能只依赖建模软件单位。

### 3. 几何和材质

P0 模型应当：

- 低到中等面数；
- 轮廓优先；
- 平滑但不过分圆润；
- 1～2 个主要材质；
- 不依赖高频纹理；
- 不依赖复杂法线贴图；
- 远景对象准备简化剪影版本。

材质建议：

| 对象 | 材质方向 |
|---|---|
| 门框、纪念石座 | 程序化 PBR，低饱和石膏/陶瓷 |
| 门光、窗光、花束 | Unlit 或 PBR + 低强度 Emissive |
| 枢轴 | 低粗糙度陶瓷或克制金属 |
| 观察窗 | 透明 PBR，低透明度 |
| 阿尔吉侬 | Unlit 或受控 PBR，保持浅色轮廓 |
| 远景剪影 | Unlit |

### 4. 资产边界表

每个非体素资产进入关卡前，都应该声明：

```text
是否拥有 PathNode：否
是否生成 Path Graph 边：否
是否参与视觉连接评估：仅作为可能的遮挡对象
是否可旋转：否，或跟随指定 Part
是否可交互：按剧情需要
是否允许遮挡可走面：默认否
是否拥有独立叙事状态：按对象声明
```

默认规则：

```text
非体素装饰不拥有路径节点；
非体素装饰不创建 Path Graph 边；
非体素装饰不能遮挡道路；
非体素装饰只能作为表现层和叙事层。
```

## 十一、暂不列入 P0 的对象

以下对象以后可能制作，但当前不应抢占剧情级 P0：

- 完整面包店模型；
- 大量家具；
- 研究人员角色；
- 爱丽丝完整人物模型；
- 复杂实验室设备；
- 远景城市整套资产；
- 树木和灌木库；
- 复杂塔顶；
- 大量粒子装饰；
- 角色服装；
- 完整过场场景套件。

这些内容不是没有价值，而是当前没有门、阿尔吉侬、花和墓那样的主线复用强度或情绪不可替代性。

## 十二、实际制作优先级

### 如果只能做 3 个资源包

```text
1. DoorKit
2. Algernon
3. MemorialStone + FlowerBouquet
```

`Charlie` 虽然属于 P0，但当前暂缓制作，不计入本阶段的执行顺序。

理由：

- DoorKit 负责章节结构；
- Algernon 负责角色记忆；
- MemorialStone 和 FlowerBouquet 负责终章收束。

### 如果可以做完整 P0

```text
1. DoorKit
2. Algernon
3. ObservationWindow
4. MemorialStone
5. FlowerBouquet
```

`Charlie` 已纳入 P0 计划，但本阶段保持暂缓；`ObservationConsole` 仍为 P0.5。

### 推荐的验证场景

不要一开始制作全套关卡。用同一个现有旋转塔白盒做两次对照：

1. 第一章暖灰低处版本；
2. 第三章冷白高塔版本。

分别加入：

- 一个门框；
- 一个门扇；
- 一个查理；
- 一个观察窗；
- 一个阿尔吉侬。

验证：

- 这些资产是否增强了章节身份；
- 是否仍能看清 PathNode 和可走面；
- 是否干扰视觉连接评估的画面判断；
- 是否比纯体素白盒更容易记住剧情对象；
- 是否像同一个世界的不同阶段。

验证成功后，再制作纪念石座和花束。

## 十三、最终判断

### 不建议的方向

```text
所有建筑继续由三棱柱体素组成，
门、窗、枢轴、花束、墓碑和远景塔也全部体素化。
```

这会保留技术特色，但缺少美术层级和叙事记忆点。

也不建议：

```text
保留一个体素白盒，
正式版全部替换成普通 3D Mesh。
```

这会损害错视玩法的核心可解释性。

### 建议的方向

```text
核心可变路径 = 三棱柱体素
固定建筑轮廓 = 模块化 3D Mesh
机关身份 = 特定 standalone 3D 模型
人物与叙事物件 = 独立 3D 模型
天空、雾、光 = 渲染与章节色彩脚本
```

最准确的项目定位是：

> **不是“体素游戏 + 3D 装饰”，而是“体素负责空间逻辑，3D 素材负责世界身份”。**

P0 最终由六个资源包组成：

```text
DoorKit
Charlie
Algernon
ObservationWindow
MemorialStone
FlowerBouquet
```

另有一个 P0.5 资源包：

```text
ObservationConsole
```

其中门是第一优先级。它是跨章节反复出现、能表达进入与离开、能承载打开与封闭、还能作为环境状态余波的最佳剧情级 standalone 资产。
