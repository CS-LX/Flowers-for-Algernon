# 六边形纪念碑谷：美术风格、色彩脚本与渲染方案调研

## 文档定位

本文是本项目的**美术研究与实施建议**，不是最终风格定案，也不是具体美术资产制作清单的替代品。

当前目标是回答四个问题：

1. 纪念碑谷系列的视觉语言中，哪些内容有公开资料支持；
2. 轻叙事游戏如何让色彩、空间和材质承担故事；
3. 纪念碑谷可能使用了哪些着色与后处理思路，哪些能够在 UrhoX 中稳妥复现；
4. 本项目五个叙事章节应如何形成可验证的色彩、场景、shader 和后处理方案。

本文区分三类结论：

- **公开事实**：来自开发者演讲、开发者访谈、官方/平台资料；
- **行业或社区推断**：来自社区仿作、技术分析和截图提取，不等同于官方实现；
- **本项目建议**：结合当前六边形三棱柱、固定正交相机和 Path Graph 玩法提出的方案。

在没有完成实际截图验证前，所有章节色板和后处理参数都属于**候选方案**，不应直接升级为产品规范。

## 一、研究摘要

### 1. 纪念碑谷可确认的核心视觉语言

公开资料较稳定地支持以下结论：

- M.C. Escher 的不可能几何是重要灵感来源；
- 关卡空间不是背景，而是主要的交互对象和视觉叙事载体；
- 团队将游戏定位为审美体验，而不只是高难度谜题；
- 设计目标之一是让每个画面都具备独立的艺术品感；
- 建筑、角色行动和路径变化承担了大量叙事功能；
- 作品使用极简、几何、低视觉噪声的构图，让玩家能看懂空间关系；
- 《纪念碑谷 2》把母女关系直接转化成角色间的空间关系和合作行为；
- 《纪念碑谷 3》进一步把光、灯塔、自然和建筑环境纳入叙事主题。

因此，本项目不应简单复制“粉色、青色、低模”这几个表面特征。更值得借鉴的是：

```text
固定视角
  + 清晰几何
  + 有控制的色彩变化
  + 角色行动作为叙事句子
  + 关卡结尾的环境状态变化
```

### 2. 不能当作官方事实的内容

公开资料没有给出纪念碑谷完整的官方渲染源码、材质节点、色彩规范、后处理堆栈或关卡 Graph 实现。因此以下说法只能作为社区仿作或技术推断：

- 官方必然使用了某一种面法线着色 shader；
- 官方完全没有实时阴影；
- 官方固定使用某一组 RGB/Hex 色板；
- 官方使用了特定的屏幕空间描边、SSAO 或 Sobel；
- 官方使用某个具体 Unity 后处理插件或某种 LUT。

社区复现普遍采用以下替代方案：

- 固定正交相机；
- 按表面方向或法线分配不同颜色；
- 用简化的方向光维持一致的明暗方向；
- 用烘焙 AO、接触阴影或简单阴影多边形增加空间层次；
- 用模型外扩描边或屏幕空间轮廓模拟插画边缘。

这些方案说明“相似视觉效果可以被拆成若干普通技术”，但不能证明原作内部实现就是这些方案。

### 3. 对本项目最重要的结论

本项目已经有比原版更严格的玩法约束：

```text
固定正交游戏相机
  + 六向离散机关
  + 三棱柱体素
  + PathRuntime 当前有效 Graph
  + 角色自动沿图行走
```

美术系统必须服从这条链路：

- 不用纹理细节掩盖视觉接缝；
- 不用动态阴影制造错误的道路暗示；
- 不用过度后处理让投影边变软；
- 不用装饰物改变玩家对可走面的判断；
- 不用颜色直接表示“智力值”或“正确答案”。

本项目最适合采用：

> **简化几何 + 分面色彩 + 软方向光 + 低强度大气雾 + 章节色彩脚本**。

自定义 shader 应该作为增强层，而不是第一版视觉成立的前提。

## 二、纪念碑谷视觉语言调研

### 1. 形体：建筑先于材质

纪念碑谷式场景的识别度首先来自轮廓和空间关系，而不是纹理。

适合本项目的几何特征：

- 方柱、三角柱、阶梯、拱门、平台、悬空体块；
- 重复但有节奏的模块化结构；
- 少量圆环、转轴、窗洞作为机关或视觉焦点；
- 清楚的顶面、侧面和底部阴影面；
- 远景使用大轮廓剪影，不使用密集小道具；
- 用空白区域衬托一个真正重要的建筑关系。

应避免：

- 砖缝、木纹、大理石纹理等高频表面细节；
- 过多栏杆、装饰柱和小型可交互物；
- 会与三棱柱边界混淆的圆润软体建筑；
- 用真实建筑比例堆叠出压迫性的复杂城市；
- 只为“看起来丰富”而添加无法服务玩法的模型。

### 2. 构图：每个画面都应该有一个空间命题

固定相机下，每一关应先用截图判断构图，而不是先看模型数量。

建议每关只保留以下层次：

```text
背景层：天空渐变、远景剪影、低对比度雾
中景层：主要建筑、机关、门或观察台
前景层：起点、目标、角色和可点击路径
```

第一眼的视觉优先级应当是：

1. 角色当前所在位置；
2. 目标位置；
3. 能改变路径的机关；
4. 可能形成视觉连接的道路边；
5. 叙事道具和远景环境。

若背景建筑比机关更亮、更饱和，玩家会误读视觉重点。若地面网格比可走面更强，玩家会把工具界面当成世界规则。

### 3. 色彩：章节变化，而不是全局彩虹

社区对纪念碑谷截图的色彩提取显示出明显的章节和关卡差异，但这些 RGB/Hex 数值不是官方发布的色彩标准。较稳定的规律是：

- 大面积使用柔和、低到中等饱和度颜色；
- 用少量高饱和色建立角色、机关或目标焦点；
- 同一画面内的颜色数量受控；
- 每个关卡可以有独立色相，但系列整体保持和谐；
- 颜色常常与空间情绪、环境主题和关卡节奏一起变化。

本项目不应把每个三棱柱扇区继续渲染成红橙黄绿蓝紫循环。那是编辑器材质，不是成品色彩脚本。

### 4. 材质：纸艺感不是纸张纹理

“魔幻纸艺工程”更适合被理解为一种视觉感受：

- 形体干净；
- 边缘明确；
- 材质不抢结构；
- 光照像插画中的受控明暗；
- 建筑看起来可被拼装、折叠和重新排列。

因此第一版不需要纸张法线贴图或真实纸纤维。程序化纯色 PBR 或 Unlit 材质就足够作为基础。材质差异主要通过：

- 顶面与侧面明度差；
- 不同建筑块的低饱和色相差；
- 粗糙度差异；
- 极少量玻璃、陶瓷或金属作为章节语义标记。

## 三、轻叙事游戏的美术叙事方法

### 1. 色彩脚本不是装饰表，而是状态表

《Journey》《GRIS》《Firewatch》等轻叙事作品表明，颜色可以承担时间、情绪和世界状态的变化。可迁移的不是“某种颜色固定代表某种情绪”，而是：

```text
玩家经历了什么
  -> 世界的色彩关系发生什么可观察变化
  -> 玩家因此重新理解之前的空间
```

本项目的色彩变化应绑定玩法和章节状态：

- 早期：道路少，世界低矮，暖色只保护角色和起点；
- 中期：可见连接增多，建筑更高更通透，青色和浅色扩大；
- 高峰：空间最丰富，但人物在画面中变小，冷白和玻璃色增加；
- 衰退：不是画面变脏，而是有效连接减少，颜色饱和度和远景层次一起退去；
- 结尾：复杂机关消失，真实道路和一束花获得最高视觉权重。

### 2. 环境叙事的三种可靠方式

#### A. 反复出现的空间

同类建筑在不同章节中重复出现，但状态不同：

- 同一座旋转塔从完整变成空置；
- 同一种门从关闭、亮起到熄灭；
- 同一种道路从真实相邻变成视觉连接，再变成不可用连接。

这比为每一章制作全新建筑更适合本项目，也能让玩家读懂“世界发生了变化”。

#### B. 角色位置和行动

阿尔吉侬不需要立即成为第二套控制系统。它可以通过：

- 提前走过一条路；
- 在远处等待；
- 停在曾经可以通过的节点；
- 在查理抵达后消失在建筑背后；

承担叙事功能。玩家看到的是行为，不是说明文字。

#### C. 可操作状态留下余波

关卡完成后，至少有一个可见状态变化：

- 门打开；
- 远处窗户亮起；
- 某座塔停止旋转；
- 远景道路出现或消失；
- 阿尔吉侬改变位置；
- 花园中出现一束花。

余波不应该改变已经完成的 Path Graph 逻辑，除非它是下一关的明确初始状态。表现层和关卡状态需要保持职责分离。

### 3. 文本和视觉的边界

建议保持以下优先级：

```text
空间关系
  > 角色行动
  > 机关反馈
  > 环境声音
  > 短文本
  > 长过场
```

文本只补充无法从画面可靠推断的内容，例如：

- 实验报告的日期或地点；
- 阿尔吉侬状态发生变化；
- 章节之间的时间跳跃；
- 一句不解释谜题、但改变情绪理解的记录。

不要用文本解释：

- 哪两条路在视觉上连接；
- 玩家刚刚旋转了什么；
- 颜色代表什么数值；
- 这座塔“象征”查理的哪一种能力。

### 4. 留白必须作为资产预算

轻叙事游戏不是每个空间都填满信息。安静关卡需要：

- 更长的视线；
- 更少的色相；
- 更慢或更短的移动；
- 更少的机关反馈；
- 角色停留和远景声音。

因此章节预算不能只计算模型数量，也要保留“低信息密度”的画面段落。

## 四、shader、光照和后处理调研结论

### 1. 公开证据的可信边界

目前能确认的只有视觉目标和若干公开技术方向，无法确认纪念碑谷官方内部的完整 shader。以下表格用于指导本项目，不用于宣称复原原作。

| 技术方向 | 证据等级 | 对本项目的判断 |
|---|---|---|
| 固定正交/等距式相机 | 高 | 已是本项目玩法基础，必须保持 |
| 面方向差异化着色 | 中 | 社区复现常用，适合三棱柱，但先做材质分面再做 shader |
| 简化方向光 | 中 | 适合维持错视可读性，优先于复杂实时光照 |
| 烘焙或简化 AO | 中低 | 可增加接触感，但不能遮暗视觉接缝，后置验证 |
| 无实时阴影或弱阴影 | 中低 | 是社区分析常见判断，不是官方确认；本项目应以可读性测试决定 |
| 模型外扩描边 | 中低 | 可作为角色/机关强调，不应给所有三棱柱强描边 |
| 屏幕空间 Sobel/ID 描边 | 低 | 固定视角可用，但会增加边缘误判和渲染验证成本，暂不优先 |
| LUT/统一调色 | 低 | 可用于章节统一，但移动端和资源裁剪需验证，先用 Zone 预设 |

### 2. UrhoX 可用技术分层

#### 层级 0：不用自定义 shader，先验证美术方向

适合首轮美术样片：

- 不透明建筑：`Techniques/PBR/PBRNoTexture.xml`；
- 角色、点击反馈、远景剪影：`Techniques/NoTextureUnlit.xml`；
- 透明玻璃或薄雾装饰：`Techniques/PBR/PBRNoTextureAlpha.xml`；
- 通过每个面或每类建筑块的材质颜色制造明暗分区；
- 通过 `LightGroup/Daytime.xml`、`Dusk.xml` 等预设测试章节氛围。

这一层最重要，因为它能证明：**颜色和构图本身是否成立**，而不是把问题推给 shader。

当前第一版已落地为：

```text
Part.look
  -> Unlit Surface Shader
  -> dot(世界法线, lightAxis) ∈ [-1, 1]
  -> colorNeg / colorMid / colorPos

LevelDocument.atmosphere
  -> 覆盖 LightGroup Zone 的雾 / Bloom / Vignette
  -> 不新建 Zone，AutoExposure 关闭
```

体素不再走 PBR 彩虹白盒色。shader 必须是 Unlit：分面颜色已经编码了明暗，再走 Lit 会二次乘光、把面色冲掉。

隔离实验室已验证的公式与踩坑见 `docs/voxel-surface-shader-lab.md`。不要在 fragment 里对 CustomGeometry 使用 `NORMAL`，不要给棱柱加 `world_vertex_coords`，世界法线必须用 `transpose(mat3(MODEL_MATRIX)) * NORMAL`。

#### 层级 1：自定义分面色彩 Surface Shader

当层级 0 已经证明色板有效后，可尝试一个非常窄的 Surface Shader：

```text
输入：表面法线、世界位置、基础色
输出：方向相关的低频色相/明度变化
```

可尝试的效果：

- 顶面自动变亮；
- 左右可见侧面使用两个受控的暗部色；
- 随世界高度或章节状态增加极轻的色彩渐变；
- 不依赖纹理，保持三棱柱轮廓清晰。

第一版不应在 shader 中根据屏幕位置直接改变 PathNode 或道路边颜色。玩法的视觉评估仍只使用固定相机投影和逻辑数据，渲染 shader 不能反向定义 Graph。

#### 层级 2：局部语义效果

只给明确的叙事对象使用：

- 门的边缘柔和发光；
- 研究所窗户的低强度冷光；
- 终章花束的轻微自发光或颜色呼吸；
- 旋转机关的枢轴状态反馈。

这些效果使用 `MatEmissiveColor` 或窄范围 Surface Shader 即可，不应让整座建筑发光。

#### 暂不使用的方案

- 手写底层 `.glsl` 或 Technique XML；
- 依赖 `canvas_item`、`sky`、`fog` 等当前 gameplay Surface Shader v1 未覆盖的类型；
- 把全屏后处理 shader 当作主要美术解决方案；
- 未经验证的实时 SSAO、屏幕空间描边和复杂透明叠加；
- 让 shader 根据相机深度自动生成玩法连接。

### 3. 光照策略

项目内 LightGroup 预设已经同时包含 Zone 和方向光。加载后不应重复创建普通 Zone 覆盖它。

建议先采用三种光照基线：

| 基线 | 预设 | 用途 |
|---|---|---|
| 温暖低处 | `LightGroup/Dusk.xml` | 第一章、面包店、旧街区 |
| 清晰白天 | `LightGroup/Daytime.xml` | 第二章研究所、高峰前段 |
| 冷静夜/冷白 | `LightGroup/Night.xml` 或 `Midnight.xml` | 高峰、衰退的对照测试 |

具体使用哪个预设，要以真实 Preview 截图判断，不以名称直接断定最终效果。

固定正交解谜优先满足：

- 同一章节内主光方向稳定；
- 顶面和侧面的明度关系稳定；
- 阴影不切断候选视觉接缝；
- 角色不被建筑阴影吞掉；
- 背景雾色与天空地平线保持连续。

自动曝光默认关闭。它适合室内外大幅明暗切换，但会让固定构图的颜色基线漂移，并增加移动端成本。

### 4. 后处理策略

#### 应优先使用

1. **低强度深度雾**：分离远景，帮助章节建立空气感；
2. **极弱 Vignette**：只在章节高潮或衰退段使用；
3. **轻微 Bloom**：只用于门、窗、花等语义对象，不能照亮所有建筑。

公开资料不能证明纪念碑谷开了引擎级 HDR / ACES。2014 Unity 移动端正交插画更像直接画色，而不是 HDR 再压回 sRGB。本项目 Unlit 分面色已经是最终色，`renderer.hdrRendering` 默认关闭；写出前 `pow(2.2)` 才能和 Inspector 色板对齐。Bloom 不依赖 HDR，普通 Part Look 不会开花。实验记录见 `docs/color-truth-lab.md`。

#### 应谨慎使用

- Gaussian Blur：只用于暂停/弹窗背景，不用于正常关卡；
- AutoExposure：只在确有明暗过渡需求时验证；
- 高强度 Vignette：会压暗边缘节点，影响点击和道路判断；
- 浓雾：会让视觉连接评估结果和玩家看到的边线产生冲突；
- 透明玻璃：必须检查深度顺序，不能用半透明物挡住真正的道路。

#### 第一版不应使用

- 全屏色差、胶片颗粒、扫描线、镜头畸变；
- 强烈径向模糊；
- 画面抖动或持续镜头晃动；
- 让颜色随角色移动位置剧烈变化的后处理。

纪念碑谷式体验依赖玩家相信自己的眼睛。后处理越强，玩家越难判断到底是空间在变化，还是画面被效果改变了。

## 五、本项目五章的候选美术方案

以下色板是**本项目候选色板**，不是纪念碑谷原作色板，也不是最终定案。所有颜色都应在实际三棱柱 Preview 中测试，尤其要检查顶面、侧面、远景雾和角色之间的对比度。

### 章节一：愿望 / 跑不过的迷宫

#### 情绪关键词

低处、日常、笨拙但温暖、真实道路、第一次希望。

#### 场景风格

- 低矮平台和短楼梯；
- 面包店或旧街区只保留轮廓，不做写实店铺；
- 中央旋转结构明显但不神秘化；
- 远景少，视线集中在起点、机关和目标；
- 建筑像未上釉的暖色石膏或陶土模型。

#### 候选色板

| 用途 | Hex | 说明 |
|---|---|---|
| 天空/雾 | `#C9C2B4` | 暖灰米色，避免编辑器蓝灰 |
| 建筑主色 | `#E4D8C7` | 暖石膏 |
| 建筑侧面 | `#B6A99A` | 低对比阴影面 |
| 可走顶面 | `#F1E6D5` | 只提高明度，不改成纯白 |
| 旧街区点缀 | `#A98762` | 木色/陶土色 |
| 查理 | `#D9AD55` | 暖黄，画面内唯一稳定的生命色 |
| 阿尔吉侬 | `#EEE8DC` | 小而浅，作为先行者 |

#### Shader / 光照

- 层级 0 程序化 PBR 为主；
- 顶面与侧面使用两档材质颜色；
- 不使用玻璃和强自发光；
- 方向光柔和，阴影只提供体块接触感。

#### 后处理

- 使用 `Dusk` 或经过调色的 `Daytime` 作为对照；
- 低强度雾；
- Vignette 关闭或极弱；
- Bloom 关闭。

#### 叙事美术动作

第一次旋转成功后，不立刻加新模型。让远处一扇原本暗着的门亮起，查理和阿尔吉侬一起进入下一段空间。门的亮度变化就是章节结尾的视觉句号。

---

### 章节二：实验 / 打开的世界

#### 情绪关键词

好奇、打开、理解扩大、空间变高、第一次看见系统。

#### 场景风格

- 建筑高度明显增加；
- 青瓷、玻璃蓝和浅金色形成研究所语言；
- 多 Part 之间留出更大空隙，让跨 Part 视觉连接可见；
- 观察窗、平台和桥梁代替大量实验室道具；
- 远景出现可重复的研究所塔群。

#### 候选色板

| 用途 | Hex | 说明 |
|---|---|---|
| 天空/雾 | `#D9E7EA` | 冷而明亮的灰青 |
| 建筑主色 | `#B7D2D0` | 低饱和青瓷 |
| 建筑侧面 | `#78999D` | 稳定的蓝灰侧面 |
| 可走顶面 | `#E8F0E7` | 淡绿白，保持空间清晰 |
| 机关点缀 | `#D7B86A` | 浅金色，不使用警报红 |
| 查理 | `#DDB85C` | 保持角色连续性 |
| 连接反馈 | `#F2D991` | 只在成功 Snap 后短暂出现 |

#### Shader / 光照

- 继续以程序化 PBR 为主；
- 可测试层级 1 分面色彩 shader，让顶面自动受控变亮；
- 玻璃只用于少量观察窗，使用透明 PBR 时必须验证深度；
- 连接反馈可以使用 Unlit 环或极弱 emissive，不把接缝本身染成永久高亮。

#### 后处理

- `Daytime` 为基线；
- 远景雾稍微减弱，允许看见研究所层次；
- 轻微 Bloom 仅用于门、窗和成功状态；
- Vignette 关闭。

#### 叙事美术动作

每完成一组关卡，远处的研究所结构增加一层或一扇窗，而不是显示“智力等级”。玩家通过空间扩大感受到变化。

---

### 章节三：高峰 / 高处没有朋友

#### 情绪关键词

清醒、明亮、孤独、被观察、看见太多却无法靠近。

#### 场景风格

- 最高的建筑和最大的留白；
- 冷白、淡紫、玻璃蓝为主；
- 研究所观测台和透明桥梁少量出现；
- 人物和远处生活被压缩成小剪影；
- 不用复杂装饰表达“高峰”，用高度、空气和空白表达。

#### 候选色板

| 用途 | Hex | 说明 |
|---|---|---|
| 天空/雾 | `#E7EEF2` | 近白冷天空 |
| 建筑主色 | `#D9DCE3` | 冷白石膏 |
| 建筑侧面 | `#9EA8BB` | 淡蓝紫暗面 |
| 玻璃/观察窗 | `#A8C7D7` | 低饱和透明蓝 |
| 观测灯 | `#E6C97A` | 少量暖色孤点 |
| 查理 | `#D8AE59` | 在冷白空间中成为孤独暖点 |
| 阿尔吉侬 | `#F5F1E8` | 远处几乎接近背景，但要保留轮廓 |

#### Shader / 光照

- 可测试层级 1 分面色彩；
- 玻璃和透明对象总量严格限制；
- 不使用全屏描边来补救透明物可读性；
- 对重要门、观察灯使用低强度 emissive；
- 阴影不能覆盖视觉候选道路边。

#### 后处理

- 使用清晰、低雾的白天基线；
- Bloom 比第二章稍明显，但只作用于语义光源；
- 极弱 Vignette，使画面中心的人物和目标稍有聚焦；
- AutoExposure 默认关闭，除非真实截图证明玻璃/白建筑明显过曝。

#### 叙事美术动作

高峰结束时不做崩塌大演出。让阿尔吉侬在一条曾经成立的路上停下。画面颜色和建筑基本不变，变化只来自角色行动停止和一条旧连接不再打开。这样玩家会先从玩法上感到异常，再从短文本或声音得到确认。

---

### 章节四：衰退 / 道路正在消失

#### 情绪关键词

褪色、失去、安静、旧空间重新出现、没有惩罚玩家。

#### 场景风格

- 复用第一、二章的建筑模块，但降低饱和度；
- 让曾经明亮的门和窗变暗；
- 让远景层次被雾吞回去；
- 空间仍然清楚，不做脏污、腐败和恐怖裂纹；
- 关卡复杂度下降时，画面也减少装饰和色彩信息。

#### 候选色板

| 用途 | Hex | 说明 |
|---|---|---|
| 天空/雾 | `#B8B8B2` | 中性褪色灰 |
| 建筑主色 | `#C6C4BC` | 失去暖色的石膏 |
| 建筑侧面 | `#858C8D` | 冷灰蓝阴影 |
| 可走顶面 | `#DEDCD1` | 仍需清晰可走 |
| 残留青色 | `#8FA9AA` | 只保留少量过去的色彩 |
| 失效反馈 | `#A98D87` | 柔和灰玫瑰，不使用警报红 |
| 查理 | `#CFAE63` | 角色仍比环境暖，但饱和度降低 |

#### Shader / 光照

- 禁止通过降低玩家移动速度或操作反馈表达衰退；
- 通过材质颜色、雾和门光状态表达环境改变；
- 视觉连接评估仍由 PathRuntime 决定，shader 不参与连接判定；
- 不使用抖动、噪波、撕裂等故障效果；
- 自发光对象逐步关闭，但要保留目标可读性。

#### 后处理

- 增加低强度灰雾；
- Vignette 可以比前章略高，但不能压暗屏幕边缘节点；
- Bloom 降低；
- 不使用强烈色调分离或黑白滤镜；
- 可在章节关键关使用 `Sandstorm` 风格的暖灰光照做对照，但必须以截图验证天空和雾的接缝。

#### 叙事美术动作

旧关卡的建筑模块重新出现，但原本的色彩标志和远景道路不再完整。玩家会认出“这是以前来过的地方”，同时发现世界不再愿意提供同样多的视觉连接。

---

### 章节五：纪念 / 给阿尔吉侬的花

#### 情绪关键词

真实、低处、安静、纪念、仍然能够完成的动作。

#### 场景风格

- 高度回到地面；
- 以稳定的局部固定边为主；
- 花园、草地、石座和一条真实道路；
- 不再出现复杂旋转塔或透明桥；
- 让空白和近距离构图替代前几章的宏大空间。

#### 候选色板

| 用途 | Hex | 说明 |
|---|---|---|
| 天空/雾 | `#D5D0C4` | 温和的暖灰 |
| 石座/建筑 | `#D8D0C0` | 安静的浅石色 |
| 草地 | `#899A7D` | 灰绿，不做鲜艳草坪 |
| 道路顶面 | `#EFE5D2` | 真实、稳定、清楚 |
| 查理 | `#D3A952` | 保持生命色 |
| 阿尔吉侬墓标记 | `#F4EFE4` | 浅色小标记 |
| 花束 | `#BE5868` | 全游戏最饱和的主色 |

#### Shader / 光照

- 不引入新 shader；
- PBR 或 Unlit 的基础材质足够；
- 花束可使用极弱 emissive，但不做闪烁；
- 角色和花的颜色对比优先于建筑质感。

#### 后处理

- 低雾、低 Bloom；
- Vignette 关闭或极弱；
- 不使用高峰期的冷白高光；
- 让花束成为画面焦点，但不使用通关爆炸或奖励特效。

#### 叙事美术动作

查理把花放下，建筑不再改变。画面停留在一条真实道路、一个墓/石座和一束花上。结尾的视觉重点不是“解锁了什么”，而是“这件事被记住了”。

## 六、项目资产规划

### 1. 第一批不需要生成的内容

以下内容当前可以直接由程序化几何和颜色完成：

- 三棱柱体素；
- 石膏平台、阶梯、墙和塔；
- 旋转机关主体；
- 门、窗和观察台的基础体块；
- 起点、目标、点击反馈；
- 查理和阿尔吉侬的简化胶囊/小体块。

不应为了验证色板而提前制作高精度模型。

### 2. 第一批值得制作的美术资产

按优先级排序：

#### 优先级 A：改变整体气质

1. 章节天空/雾色板；
2. 建筑顶面、侧面和底面三档颜色；
3. 查理与阿尔吉侬的稳定角色色；
4. 旋转机关的六向枢轴视觉标记；
5. 门和窗的低强度发光材质。

#### 优先级 B：建立章节辨识度

1. 第一章旧街区剪影模块；
2. 第二章研究所塔群和观察窗；
3. 第三章少量透明桥/玻璃台；
4. 第四章褪色旧建筑变体；
5. 第五章草地、石座和花束。

#### 优先级 C：最后才做

1. 角色服装和面部细节；
2. 高精度建筑装饰；
3. 复杂粒子；
4. 章节专属全景图；
5. 过场动画中的独立场景资产。

### 3. 资源制作原则

- 一个资产至少要在两个关卡中复用，除非它是明确的叙事终点；
- 资产先以轮廓和材质球验证，再制作纹理；
- 任何新颜色都要在固定相机截图中和角色、道路、背景同时检查；
- 任何透明资产都要做深度和遮挡回归；
- 任何发光资产都要检查是否误导视觉连接；
- 花束是唯一允许拥有明显高饱和装饰细节的终章物件。

---

## 七、建议的落地验证顺序

### 阶段 1：色彩样片，不改玩法

使用现有旋转塔白盒，制作至少两张 Preview 对照：

- 第一章低处暖灰石膏；
- 第三章高峰冷白高塔。

只改变：

- 建筑材质颜色；
- 地面/天空/雾色；
- LightGroup 预设或 Zone 参数；
- 角色颜色。

不改变：

- Path Graph；
- 机关 Snap；
- 相机角度；
- 点击和角色移动逻辑。

验证问题：

1. 起点、目标、机关是否仍然一眼可辨；
2. 错视接缝是否比白盒更清晰，而不是更模糊；
3. 角色是否始终可见；
4. 远景是否支持空间层次而不抢主体；
5. 两张图是否像同一个世界的两个阶段。

### 阶段 2：三档分面材质

用程序化材质验证：

```text
顶面：高明度主色
可见侧面 A：主色降低明度
可见侧面 B：主色降低明度并轻微偏色
```

这一阶段先不写 Surface Shader。若三档材质已能保持空间清晰，说明自定义 shader 不是视觉方向的必要条件。

### 阶段 3：窄范围 Surface Shader 探针

只在独立材质样片中测试：

- 法线方向分面色；
- 世界高度的极轻渐变；
- 单个门或窗的 emissive。

每次只验证一个效果，不能同时替换整个 Preview 渲染链路。若出现黑屏、纸片、颜色漂移或边缘回归，立即保留层级 0 作为基线。

### 阶段 4：章节后处理对照

对同一关卡分别测试：

- 无 Vignette / 低 Vignette；
- 无 Bloom / 语义对象 Bloom；
- 清晰雾 / 灰雾；
- Daytime / Dusk / Night。

比较应基于真实 Preview 截图，而不是只看 API 是否可调用。

### 阶段 5：叙事资产加入

在色板和渲染基线稳定后，按顺序加入：

1. 阿尔吉侬远处移动或停留；
2. 门/窗状态余波；
3. 研究所远景；
4. 褪色状态；
5. 花园和花束。

不要先制作完整剧情过场或双角色同步玩法。

## 八、验收清单

### 风格一致性

- [ ] 编辑器彩虹材质与 Game Preview 叙事材质已分离；
- [ ] 同一章节没有无意义的多色循环；
- [ ] 建筑轮廓比材质纹理更突出；
- [ ] 远景对比度低于中景；
- [ ] 角色始终与建筑存在稳定冷暖或明度对比；
- [ ] 每章有一个主色和有限的点缀色。

### 玩法可读性

- [ ] 起点、目标和机关第一眼可辨；
- [ ] 可走顶面不会被雾、阴影或后处理吞掉；
- [ ] 视觉连接边仍然清晰；
- [ ] 发光效果不会伪造 Path Graph 连接；
- [ ] 透明对象不会遮挡真正的道路；
- [ ] 旋转动画期间画面不会因后处理产生错误反馈。

### 叙事表达

- [ ] 章节色彩变化对应世界状态，而非单纯换皮；
- [ ] 至少一个重复建筑在不同章节呈现不同状态；
- [ ] 阿尔吉侬通过位置和行动表达，不依赖长对白；
- [ ] 衰退没有被表现成玩家操作能力下降；
- [ ] 终章降低复杂度，花束承担视觉终点；
- [ ] 删除文本后，玩家仍能理解主要空间变化。

### 技术安全

- [ ] 程序化材质只使用项目允许的 Technique；
- [ ] LightGroup 加载后没有被错误的高优先级 Zone 覆盖；
- [ ] Surface Shader 只在独立样片验证后进入正式 Preview；
- [ ] 没有用 shader 或后处理反向定义 Path Graph；
- [ ] 固定相机、Overlay、深度和真实像素结果完成回归检查；
- [ ] 移动端或不同 Preview 后端的差异被单独记录。

---

## 九、当前建议，不是最终定案

基于本轮调研，当前最值得验证的方向是：

> **低饱和建筑色块 + 稳定分面明暗 + 固定正交构图 + 章节色彩脚本 + 极少量语义发光。**

建议暂时不要定死以下内容：

- 是否全局使用黑色描边；
- 是否使用自定义面法线 shader；
- 是否加入实时 AO；
- 是否使用完整 LUT 调色；
- 是否制作纸张纹理；
- 是否为每章制作独立天空盒；
- 是否把《纪念碑谷》的具体截图色值作为项目标准。

艺术方向的下一步应是**两张同一白盒关卡的章节对照样片**，而不是直接批量生成全部素材。只有当这两张样片证明“颜色变化能够表达阶段变化，同时不损害错视可读性”，才有理由继续锁定章节规范。
