# 六边形纪念碑谷技术验证计划

## 项目定位（先读）

**我们现在正在做的是一个“六边形纪念碑谷”错视解谜游戏的核心玩法验证。**

本项目的最终目标不是制作一个独立的三棱柱体素编辑器，而是验证下面这条可玩闭环：

```text
固定正交视角下观察六边形建筑
  -> 操作六向建筑机关
  -> 建筑状态改变视觉对齐关系
  -> 逻辑导航图出现新的连接
  -> 小人沿导航图自动行走到目标
```

三棱柱体素、Part、Object Tree 和局部体素编辑器，都是**用于搭建和验证六边形纪念碑谷关卡的制作与调试工具**，不是本项目最终要验证的独立产品方向。

本轮的成功标准是“错视解谜能走通”，而不是“编辑器功能齐全”：

- 旋转前，起点到目标不可达；
- 旋转中央六向结构后，道路在固定视角下形成错觉连接；
- 逻辑导航图显式新增该连接；
- 小人沿逻辑路径走到目标；
- Debug 层能够显示节点、边、机关状态、点击映射和最终路径。

因此阅读本计划时，应始终按以下优先级理解项目：

```text
第一优先级：六边形纪念碑谷的运行时玩法闭环
第二优先级：独立逻辑网格、导航图和机关状态
第三优先级：三棱柱体素表现与关卡制作工具
```

## 当前工作范围

当前阶段只做一个最小白盒技术验证关卡：

```text
起点平台 -> 中央六向旋转结构 -> 目标平台
```

本阶段暂不把自由相机、通用体素编辑能力或成品美术作为目标。编辑器已有功能只有在服务于这张验证关卡的搭建、运行和 Debug 时才是当前重点。

## 技术判断：相机不转，建筑状态转

### 原版机制结论

根据 2014 年原版的同期评测、关卡攻略、官方项目介绍和仿作源码研究，本项目采用以下准确表述：

- 普通解谜过程中，不提供玩家自由环绕旋转或平移的解谜相机。
- 玩家点击路径引导角色移动，拖动旋钮、平台、墙体或其他建筑机关。
- 这些建筑部件的旋转、滑动或升降改变当前受控视角下的视觉对齐关系，从而显现新的路径。
- 原版另有独立的 Camera Mode，可用于拍照时平移和缩放；这不属于本轮玩法技术验证范围。
- “相机永远完全不动”是过强表述。关卡转场或作者控制的镜头动画需要与普通解谜输入分开处理；本轮暂不实现自由相机，也不实现拍照模式。

### Path Graph 目标架构（必须遵守）

本项目不是用手写条件边模拟纪念碑谷，而是向成熟的纪念碑谷式工作流靠拢：

```text
Part 局部可走面节点与关卡候选连接
  -> 机关到达合法 Snap 状态
  -> PathRuntime 根据 Part 当前 Transform 和固定游戏相机评估视觉连接
  -> 生成当前有效 Path Graph
  -> 寻路消费 Path Graph
```

这里必须区分 **节点源数据的所有权** 和 **运行时寻路图的查询范围**：

- `VoxelDocument.pathNodes` 继续保存 Part 内局部 Cell/Face 上的 PathNode，是节点几何锚点和局部通行语义的唯一持久化源；
- PathNode 不因为寻路跨越多个 Part，就迁移或复制到 `LevelDocument`；
- `LevelDocument` 只保存 Part、层级、固定游戏相机、局部节点引用组成的关卡候选连接、固定边和设计者覆盖；
- `PathRuntime` 在运行时收集各 Part 的局部节点，建立临时 `partId:localNodeId` 索引，派生当前世界锚点和有效连接；
- `CurrentEffectiveGraph` 是运行时派生缓存和寻路唯一输入，不是新的持久化节点真相源。

关卡配置应主要描述：

- 各 Part 局部可走面节点及其面语义、方向、入口/出口语义；
- 跨 Part 候选节点对，引用 `partId:localNodeId`，不复制 Cell/Face 等节点定义；
- 节点所属的可变 Part 或机关；
- 机关的离散 Snap 状态；
- 固定游戏相机和视觉连接评估规则。

运行时应在机关到达合法状态后，使用固定游戏相机重新评估视觉连接，再生成当前有效边。视觉连接评估不是渲染层装饰，而是纪念碑谷玩法中 Path Graph 生成的一部分。

显式条件边仍可保留，但只作为：

- 不随几何变化的固定连接；
- 第一阶段白盒验证的临时兜底；
- 设计者明确覆盖自动评估的特殊连接；
- 自动评估结果的 Debug 对照。

显式条件边不能成为错视连接的长期主要配置方式，也不能因为“算法未完全公开”就替代目标架构。

### 运行时连接更新边界

```text
机关旋转动画中
  -> 只更新受影响 Part 的表现层 Transform
  -> PathRuntime 保持上一份合法 CurrentEffectiveGraph
  -> 角色若静止站在该 Part 或其子 Part 的路径节点上，则相对 Part 静止并跟随 Transform

角色正在某个可动 Part 或其子 Part 上走路
  -> 禁止玩家拖动该机关

角色静止站在某个可动 Part 或其子 Part 的路径节点上
  -> 允许拖动该机关
  -> 角色必须跟着 Part 一起运动，不得在转动中自行走路

机关到达合法 Snap 状态
  -> 提交离散机关状态
  -> PathRuntime 刷新受影响 Part 的派生节点数据
  -> 以固定游戏相机评估相关视觉连接
  -> 原子替换 CurrentEffectiveGraph
  -> 更新 topologyVersion
```

寻路只读取当前有效 Path Graph，不扫描 Mesh、Scene Node 或物理碰撞，也不反向修改 Graph。

节点源数据分布在 Part 中，寻路入口可以集中；**去中心化的节点所有权不等于去中心化的寻路查询**。

公开资料对成熟纪念碑谷式工作流的影响如下：

> **逻辑网格和当前 Path Graph 是玩法真相；但错视连接的生成应由关卡配置、机关合法 Snap 状态和固定游戏相机下的视觉连接评估共同驱动。**

具体条例如下：

1. 网格节点、可走面、机关状态和可达性属于逻辑层。
2. 体素模型、材质、碰撞体和旋转动画属于表现层。
3. 角色寻路只读取当前有效 Path Graph，不通过模型距离、场景树或物理碰撞自动推断路径。
4. 视觉对象通过 `logicalNodeId` 与逻辑节点建立映射。
5. 机关到达合法 Snap 状态后，使用固定游戏相机重新评估节点的视觉连接、深度和遮挡关系，并生成当前有效连接。
6. 显式边可以作为固定连接、临时白盒兜底、设计者覆盖或 Debug 对照，但不能成为错视连接的长期主要配置方式。
7. 任何网格、机关状态和 Path Graph 状态都必须能够脱离渲染模型独立调试和复现。

## 今日目标

完成“六边形纪念碑谷”的核心错视验证：玩家能看到一个小人在三角体素组成的建筑中行走；旋转一个六向结构后，原本在真实三维空间中不连续的两段道路，在当前正交视图中形成错觉连接，小人能够沿这条新连接走到目标。

## 验收画面

```text
起点平台 → 中央六向旋转结构 → 目标平台

旋转前：目标不可达
旋转后：道路投影边缘对齐，导航图新增连接，小人走向目标
```

## 阶段 1：建立三角体素白盒场景

- 保持正交相机与 `30°` 俯视角。
- 使用第一版三棱柱体素规范：
  - 三角形边长 `a = 1.0m`；
  - 体素高度 `h = 1 / √3 ≈ 0.57735m`；
  - 六方向离散旋转，每步 `60°`。
- 搭建起点平台、中央可旋转六向结构和目标平台。
- 使用不同颜色区分可走面、墙面与机关。
- 视觉场景的生成必须接受逻辑网格数据，不在绘制器中定义玩法连接。

**验收：** 整个谜题结构清晰可见，起点、机关与终点可辨认。

## 阶段 2：建立逻辑体素网格与可走面节点

每个可走面对应一个逻辑导航节点，而不是简单把整个体素视为一个可走点：

```lua
{
  id = "start_01",
  gridX = 0,
  gridZ = 0,
  level = 0,
  face = "top",
  walkable = true,
  partId = "start_platform",
  logicalNodeId = "start_01",
}
```

实现内容：

- 可走面节点 ID；
- 节点所属体素、Part 和机关；
- 面中心或设计锚点到逻辑节点的映射；
- 面类型、入口/出口方向和通行语义；
- 逻辑坐标到世界坐标的转换；
- 固定游戏相机下的节点投影与深度信息；
- 由机关合法 Snap 状态驱动的视觉连接评估；
- 当前有效 Path Graph 的生成；
- 逻辑节点到视觉体素节点的绑定关系。

**验收：** 不依赖模型碰撞，也能从节点配置、机关状态和固定游戏相机评估结果得出当前可走节点与连接边；替换体素模型不会改变关卡逻辑配置。

## 阶段 3：建立自动生成的 Path Graph 与寻路

- 每个可走面是一个导航节点。
- 关卡配置保存节点、面语义、机关归属和视觉连接评估所需的数据。
- 机关到达合法 Snap 状态后，使用固定游戏相机评估节点投影、深度、遮挡、方向和边界连续性。
- 根据评估结果生成当前有效 Path Graph；固定连接可以直接保留，错视连接不能依赖手写状态分支。
- 第一版寻路使用 BFS，但 BFS 只消费当前有效 Graph，不参与生成连接。
- 给定起点与终点，可以输出稳定的 node ID 路径。
- 机关未转动时，目标不可达；机关转动到视觉邻接状态后，Graph 自动出现新连接，目标可达。
- 寻路不扫描模型，不根据世界空间距离或物理碰撞自动创建边。

显式连接只作为固定边、白盒兜底、设计者覆盖或 Debug 对照，不作为错视连接的主要配置方式。

**验收：**

```text
机关初始状态：起点 → 目标，不可达
机关到达合法 Snap 状态：固定相机下视觉连接成立，Graph 自动生成连接
BFS：start_01 → rotator_entry → rotator_exit → goal_entry
```

## 阶段 4：实现小人行走

- 创建胶囊或简化人形作为白盒角色。
- 角色站在 tile 顶面。
- 点击可达 tile 后，角色自动沿导航路径移动。
- 角色在 tile 中心之间平滑过渡，并朝移动方向转向。
- 行走不使用自由物理控制。
- 角色的目标点由逻辑节点提供，再映射到对应的视觉位置。

**验收：** 小人可从起点稳定走到同一平台内的任意可达 tile。

## 阶段 5：实现六向旋转机关

- 点击或按钮触发机关。
- 每次只旋转 `60°`。
- 旋转过程平滑，结束时停在六个合法离散状态之一。
- 角色正在某个可动 Part（含其子 Part）上走路时，该机关不允许被玩家拖动。
- 角色静止站在该可动 Part 的路径节点上时，允许拖动该机关；拖动和 Snap 过程中角色必须相对 Part 静止并跟随其 Transform。
- 逻辑使用 `rotatorStep = 0..5`，不使用任意浮点 Euler 角作为玩法状态。
- 视觉旋转动画完成后，再原子地提交机关状态并更新导航图。

**验收：** 机关在六个状态间稳定切换，没有半角度状态、路径不同步或角色掉落。

## 阶段 6：验证错视连接

1. 初始状态下，起点与目标不连通。
2. 旋转建筑机关，而不是旋转解谜相机。
3. 机关到达合法 Snap 状态后，固定游戏相机下两段道路边缘对齐。
4. 视觉连接评估器确认节点、面方向、投影连续性和遮挡关系满足连接规则。
5. 当前有效 Path Graph 自动生成该连接。
6. 小人读取新的 Graph，走过这条视觉连续、三维不连续的路径。
7. 小人到达目标。

本轮不实现任意几何体的无约束自动连边，而是实现受关卡配置约束的视觉连接评估：

```text
关卡配置的可走面节点
  + 机关合法 Snap 状态
  + 固定游戏相机
  + 视觉连接规则
  -> 当前有效 Path Graph
```

评估结果可以被 Debug 层解释和复现；不允许使用模型距离、物理碰撞或编辑器自由相机直接创建玩法连接。

## 阶段 7：实现运行时网格与导航图 Debug 可视化

为了验证“网格是真相源”，运行时必须能够显示逻辑状态，而不只显示模型：

- 节点中心：显示逻辑节点位置；
- 节点标签：显示 `nodeId`、网格坐标和高度层；
- 绿色边：当前有效导航边；
- 红色边：已声明但当前关闭的条件边；
- 黄色边：机关条件未满足；
- 白色粗线：角色当前 BFS 最终路径；
- 蓝色标记：鼠标射线命中的视觉对象；
- 紫色标记：视觉对象映射后的逻辑节点；
- 机关状态：显示 `rotatorStep` 和拓扑版本号。

Debug 层必须支持至少一种开关，使以下问题可直接判断：

```text
点击命中了哪个视觉对象？
它映射到了哪个逻辑节点？
当前图中有哪些边？
哪条边被机关关闭？
小人的路径由哪些 nodeId 组成？
```

**验收：** 关闭体素表现或替换体素模型时，逻辑节点、边和路径仍能独立显示并保持一致。

## 今日最低验收线

- [ ] 三角体素白盒建筑已建立。
- [ ] 相机在普通解谜验证中保持固定，不提供自由旋转。
- [ ] 网格与导航图独立于体素模型存在。
- [ ] 小人可沿逻辑导航图移动。
- [ ] 中央机关能按 `60°` 旋转。
- [ ] 旋转前目标不可达。
- [ ] 旋转后导航图生成新连接。
- [ ] 小人穿过错视通路到达目标。
- [ ] Debug 可视化能显示节点、边、点击映射和最终路径。
- [ ] 正交相机下，画面呈现视觉连续、真实空间不连续的建筑关系。

## 本轮不做

- 普通解谜中的自由相机旋转或平移；
- 独立 Camera Mode / 拍照模式；
- 完整角色动画；
- 自动生成关卡；
- 通用 NavMesh；
- 任意几何体自动投影连边；
- 成品级美术、叙事和音频；
- 多关卡系统。

本轮只证明：三角体素、固定正交投影、离散建筑旋转、逻辑导航图和运行时 Debug 可视化组合后，能够让小人在错觉建筑中自动寻路并走起来。
