# 六边形纪念碑谷技术验证计划

## 技术判断：相机不转，建筑状态转

### 原版机制结论

根据 2014 年原版的同期评测、关卡攻略、官方项目介绍和仿作源码研究，本项目采用以下准确表述：

- 普通解谜过程中，不提供玩家自由环绕旋转或平移的解谜相机。
- 玩家点击路径引导角色移动，拖动旋钮、平台、墙体或其他建筑机关。
- 这些建筑部件的旋转、滑动或升降改变当前受控视角下的视觉对齐关系，从而显现新的路径。
- 原版另有独立的 Camera Mode，可用于拍照时平移和缩放；这不属于本轮玩法技术验证范围。
- “相机永远完全不动”是过强表述。关卡转场或作者控制的镜头动画需要与普通解谜输入分开处理；本轮暂不实现自由相机，也不实现拍照模式。

因此，本项目的第一版技术验证固定相机：

```text
相机：固定正交投影、固定俯视角
建筑：由离散机关状态驱动旋转/位移
玩法：建筑状态改变导航图，角色沿图自动寻路
```

### 研究结论对本项目的影响

公开仿作中最常见的是 `Walkable` 节点加显式 `possiblePaths` 边；较成熟的实现还会将固定边与条件边分开，在机关状态改变后更新条件边。也有仿作根据场景几何动态扫描邻居，但这种方式难以表达“视觉上对齐、逻辑上禁止通行”的错视关卡。

本项目采用更严格的解耦方案：

> **逻辑网格及其导航图是唯一玩法真相源；三棱柱体素只是网格的具象化表达。**

具体条例如下：

1. 网格节点、连接边、机关状态和可达性属于逻辑层。
2. 体素模型、材质、碰撞体和旋转动画属于表现层。
3. 角色寻路只读取逻辑导航图，不通过模型距离、场景树或物理碰撞自动推断路径。
4. 视觉对象只负责显示逻辑节点，并通过 `logicalNodeId` 与逻辑节点建立映射。
5. 视觉重合不自动等于逻辑可通行；错视连接必须由关卡数据显式声明，并由机关状态决定是否激活。
6. 后续可以用屏幕投影检测验证一条候选错视连接，但检测结果只能作为验证信息或候选边，不能绕过关卡逻辑直接修改导航图。
7. 任何网格或导航图状态都必须能够脱离渲染模型独立调试和复现。

## 今日目标

完成“六边形纪念碑谷”的核心错视验证：玩家能看到一个小人在三角体素组成的建筑中行走；旋转一个六向结构后，原本在真实三维空间中不连续的两段道路，在当前正交视图中形成错觉连接，小人能够沿这条新连接走到目标。

## 验收画面

```text
起点平台 → 中央六向旋转结构 → 目标平台

旋转前：目标不可达
旋转后：道路投影边缘对齐，导航图新增连接，小人走向目标
```

## 阶段 1：建立三角体素白盒场景

- 保持正交相机与 `30°` 俯视角。
- 使用第一版三棱柱体素规范：
  - 三角形边长 `a = 1.0m`；
  - 体素高度 `h = 1 / √3 ≈ 0.57735m`；
  - 六方向离散旋转，每步 `60°`。
- 搭建起点平台、中央可旋转六向结构和目标平台。
- 使用不同颜色区分可走面、墙面与机关。
- 视觉场景的生成必须接受逻辑网格数据，不在绘制器中定义玩法连接。

**验收：** 整个谜题结构清晰可见，起点、机关与终点可辨认。

## 阶段 2：建立逻辑体素网格

每个可走 tile 同时保存逻辑数据：

```lua
{
  id = "start_01",
  gridX = 0,
  gridZ = 0,
  level = 0,
  orientation = 0,
  walkable = true,
}
```

实现内容：

- tile ID；
- 逻辑坐标到世界坐标的转换；
- tile 中心点；
- 固定连接关系；
- 由机关状态驱动的动态连接关系；
- 逻辑节点到视觉体素节点的绑定关系。

**验收：** 不依赖模型，也能从数据得出当前可走节点和连接边；替换体素模型不会改变网格和导航结果。

## 阶段 3：建立导航图与寻路

- 每个可走 tile 是一个导航节点。
- 邻接关系和错视连接都是导航边。
- 第一版使用 BFS。
- 给定起点与终点，可以输出稳定的 node ID 路径。
- 机关未转动时，目标不可达；机关转动后，图中新边出现，目标可达。
- 寻路不扫描模型，不根据世界空间距离自动创建边。

**验收：**

```text
机关初始状态：起点 → 目标，不可达
机关旋转完成：起点 → 中央结构 → 目标，可达
```

## 阶段 4：实现小人行走

- 创建胶囊或简化人形作为白盒角色。
- 角色站在 tile 顶面。
- 点击可达 tile 后，角色自动沿导航路径移动。
- 角色在 tile 中心之间平滑过渡，并朝移动方向转向。
- 行走不使用自由物理控制。
- 角色的目标点由逻辑节点提供，再映射到对应的视觉位置。

**验收：** 小人可从起点稳定走到同一平台内的任意可达 tile。

## 阶段 5：实现六向旋转机关

- 点击或按钮触发机关。
- 每次只旋转 `60°`。
- 旋转过程平滑，结束时停在六个合法离散状态之一。
- 角色移动与机关旋转互斥。
- 逻辑使用 `rotatorStep = 0..5`，不使用任意浮点 Euler 角作为玩法状态。
- 视觉旋转动画完成后，再原子地提交机关状态并更新导航图。

**验收：** 机关在六个状态间稳定切换，没有半角度状态、路径不同步或角色掉落。

## 阶段 6：验证错视连接

1. 初始状态下，起点与目标不连通。
2. 旋转建筑机关，而不是旋转解谜相机。
3. 旋转完成后，当前正交画面中两段道路边缘对齐。
4. 导航图添加错视连接。
5. 小人走过这条视觉连续、三维不连续的路径。
6. 小人到达目标。

第一版使用预定义连接规则：

```lua
if rotatorStep == 1 then
  Connect("rotator_exit", "goal_entry")
else
  Disconnect("rotator_exit", "goal_entry")
end
```

本轮不实现任意 tile 的投影边自动识别；该能力留待后续验证。投影检测未来只能作为候选连接验证器，不能取代关卡导航图。

## 阶段 7：实现运行时网格与导航图 Debug 可视化

为了验证“网格是真相源”，运行时必须能够显示逻辑状态，而不只显示模型：

- 节点中心：显示逻辑节点位置；
- 节点标签：显示 `nodeId`、网格坐标和高度层；
- 绿色边：当前有效导航边；
- 红色边：已声明但当前关闭的条件边；
- 黄色边：机关条件未满足；
- 白色粗线：角色当前 BFS 最终路径；
- 蓝色标记：鼠标射线命中的视觉对象；
- 紫色标记：视觉对象映射后的逻辑节点；
- 机关状态：显示 `rotatorStep` 和拓扑版本号。

Debug 层必须支持至少一种开关，使以下问题可直接判断：

```text
点击命中了哪个视觉对象？
它映射到了哪个逻辑节点？
当前图中有哪些边？
哪条边被机关关闭？
小人的路径由哪些 nodeId 组成？
```

**验收：** 关闭体素表现或替换体素模型时，逻辑节点、边和路径仍能独立显示并保持一致。

## 今日最低验收线

- [ ] 三角体素白盒建筑已建立。
- [ ] 相机在普通解谜验证中保持固定，不提供自由旋转。
- [ ] 网格与导航图独立于体素模型存在。
- [ ] 小人可沿逻辑导航图移动。
- [ ] 中央机关能按 `60°` 旋转。
- [ ] 旋转前目标不可达。
- [ ] 旋转后导航图生成新连接。
- [ ] 小人穿过错视通路到达目标。
- [ ] Debug 可视化能显示节点、边、点击映射和最终路径。
- [ ] 正交相机下，画面呈现视觉连续、真实空间不连续的建筑关系。

## 本轮不做

- 普通解谜中的自由相机旋转或平移；
- 独立 Camera Mode / 拍照模式；
- 完整角色动画；
- 自动生成关卡；
- 通用 NavMesh；
- 任意几何体自动投影连边；
- 成品级美术、叙事和音频；
- 多关卡系统。

本轮只证明：三角体素、固定正交投影、离散建筑旋转、逻辑导航图和运行时 Debug 可视化组合后，能够让小人在错觉建筑中自动寻路并走起来。
