# 路径节点与 Gizmo 三阶段开发计划

## 计划定位

本计划服务于“六边形纪念碑谷”错视解谜玩法，不把路径节点做成普通 NavMesh 点，也不把 Gizmo 做成脱离玩法的通用编辑器装饰。

目标工作流是：

```text
Part 局部可走面节点
  -> PathRuntime 建立临时索引
  -> 固定游戏相机下视觉连接评估
  -> 生成当前有效 Path Graph
  -> Gizmo / Debug 显示评估结果
  -> 后续寻路和角色移动消费 Graph
```

节点的持久化所有权与寻路的查询范围必须分开：

- `VoxelDocument.pathNodes` 是 Part 局部 PathNode 的唯一持久化源；
- 节点锚定在局部 Cell/Face，不因跨 Part 寻路而复制到 `LevelDocument`；
- `LevelDocument` 只保存 Part 组合、固定游戏相机和引用局部节点的候选连接/固定边；
- `PathRuntime` 在运行时建立 `partId:localNodeId` 临时索引，并持有派生的当前有效 Graph；
- Gizmo 显示的是节点和 Graph 的派生状态，不反向修改路径真相源。

公开资料没有披露纪念碑谷内部 Gizmo 的具体颜色、图标或交互界面，因此本计划只采用已确认的成熟原则：

- 节点布置在可走空间上；
- 节点可表达可达 / 不可达状态；
- 节点支持不同通行语义；
- 几何体到达合法 Snap 状态后重新评估连接；
- 评估使用固定游戏相机的投影、深度和遮挡关系；
- 编辑器 Gizmo 必须帮助设计者理解节点、连接和评估结果。

## 阶段一：建立可走面路径节点与基础 Gizmo

### 目标

建立路径节点的数据真相源，并让节点稳定地显示在对应三棱柱的可走面上。

### 数据范围

每个路径节点至少包含：

```lua
{
    id = "start_01",
    partId = "part_static_base",
    voxelCellKey = "0:0:0:0",
    face = "top",
    kind = "floor",
    walkable = true,
}
```

必须区分：

- 体素归属；
- 面归属；
- 面类型和通行语义；
- 入口 / 出口方向；
- 节点 ID；
- 所属 Part 和可变机关。

路径节点的几何锚点默认放在**可走面的中心或面内设计锚点**，不放在体素中心、边中心或顶点。锚点位置应由面几何和局部三棱柱 Grid 派生，不能让任意浮点 Scene Node 成为逻辑真相。

### Gizmo 内容

基础 Gizmo 只显示节点本体和方向，不提前绘制未经评估的路径：

- 节点中心标记：显示在可走面上方的微小 3D 标记；
- 面法向箭头：表示站立面朝向；
- 入口 / 出口方向：使用不同方向标记；
- 节点 ID 标签：用于定位和 Debug；
- 节点状态：至少区分未验证、有效、不可用；
- 选中节点：显示所属体素、面、Part 和机关信息。

颜色和图标属于项目 Gizmo 规范，不声称是纪念碑谷官方颜色。推荐：

```text
白 / 蓝：已配置节点
绿：当前可达或评估有效
黄：候选 / 待评估
红：评估失败或不可用
紫：视觉对象到逻辑节点的映射标记
```

### 阶段验收

- 可在指定三棱柱可走面上创建、选择和删除节点；
- 节点不会错误落在体素中心、边或顶点；
- 节点拥有稳定 ID 和面语义；
- 节点移动 Part 或旋转机关后，显示位置由当前 Transform 正确派生；
- 不依赖模型碰撞生成节点；
- 关闭体素显示后，节点 Gizmo 仍可独立显示。

## 阶段二：建立路径节点 Gizmo 与视觉连接评估

### 目标

让 Gizmo 表达纪念碑谷式 Path Graph 的核心状态：哪些节点可能连接、哪些连接有效、为什么连接被拒绝。

### 关卡配置

设计者配置：

- 可走面节点；
- 节点的面类型、方向和通行语义；
- 节点所属 Part 与机关；
- 机关允许的离散 Snap 状态；
- 节点连接候选范围和视觉评估规则；
- 必要的固定连接或明确覆盖。

设计者不为每个机关状态手写全部错视连接。错视连接由运行时在合法 Snap 状态下评估生成。

### 视觉连接评估

对配置范围内的候选节点对，使用固定游戏相机检查：

- 两个可走面的屏幕投影边界是否连续或在容差内对齐；
- 入口 / 出口方向是否兼容；
- 面法向和行走方向是否满足通行语义；
- 节点和边界的相机深度顺序；
- 中间遮挡是否破坏视觉连接；
- 当前机关是否已经到达合法 Snap 状态。

评估结果生成当前有效 Path Graph。显式边只能用于固定连接、临时白盒兜底、设计者覆盖或 Debug 对照。

### Gizmo 内容

Gizmo 必须区分三种连接状态：

```text
候选连接：灰 / 黄虚线，显示“待评估”或候选原因
有效连接：绿实线，显示当前可走方向
拒绝连接：红虚线，显示拒绝原因
```

连接 Gizmo 还应支持：

- 单向 / 双向箭头；
- 连接两端节点 ID；
- 评估失败原因；
- 屏幕投影边界或对应边标记；
- 相机深度值或深度排序序号；
- 当前机关 Snap 状态；
- 当前拓扑版本号。

旋转动画中不重新提交 Graph。机关到达 Snap 状态后：

```text
提交离散机关状态
  -> 重建视觉连接评估
  -> 原子替换当前有效 Graph
  -> 刷新连接 Gizmo
```

### 阶段验收

- 旋转机关处于初始状态时，目标连接显示为拒绝或未激活；
- 机关到达视觉邻接的合法 Snap 状态后，连接自动变为有效；
- 连接 Gizmo 能解释“为什么有效 / 为什么拒绝”；
- 编辑器自由相机变化不会改变游戏 Graph；
- 只使用固定游戏相机进行视觉连接评估；
- 不使用模型距离、物理碰撞或 Scene 树自动创建连接。

## 阶段三：接入运行时 Path Graph 与独立 Debug 工作流

### 目标

将路径节点和视觉评估结果接入运行时，形成可独立验证、可复现、可供寻路消费的当前有效 Path Graph。

### 运行时流程

```text
关卡配置
  -> 可走面节点
  -> Part / 机关当前状态
  -> 固定游戏相机视觉连接评估
  -> 当前有效 Path Graph
  -> 可达区域
  -> 后续 BFS / 角色移动
```

Graph 是运行时寻路的输入，但寻路不能反向定义 Graph。Graph 与渲染模型、体素节点、物理碰撞保持分离。

### 运行时状态

必须记录：

- 当前节点集合；
- 当前有效连接集合；
- 候选和拒绝连接及原因；
- 当前机关 Snap 状态；
- `topologyVersion`；
- 评估使用的固定游戏相机配置；
- 视觉对象与 `logicalNodeId` 的映射。

### Debug 显示

运行时 Gizmo / Debug 层至少支持：

- 节点中心和面法向；
- 节点 ID、Part ID、Cell Key；
- 当前有效连接；
- 当前关闭或拒绝连接；
- 连接评估原因；
- 当前可达区域；
- 点击视觉对象后的逻辑节点映射；
- 当前机关状态和拓扑版本；
- 后续 BFS 输出的 nodeId 路径预览。

运行时 Debug 必须能回答：

```text
这个视觉对象对应哪个路径节点？
节点属于哪个可走面？
当前机关处于哪个 Snap 状态？
这两个面为什么连上或没有连上？
当前 Graph 有哪些有效边？
目标节点当前是否可达？
```

### 阶段验收

- 关闭体素表现后，逻辑节点、连接和可达区域仍可显示；
- 替换体素模型不会改变节点 ID 和 Graph 结果；
- 机关状态从一个 Snap 状态切换到另一个状态时，Graph 原子刷新；
- 旋转动画中不存在半状态 Graph；
- Graph 可保存或打印为稳定的调试数据；
- 后续 BFS 可以直接消费当前有效 Graph，不需要修改节点系统。

- [x] 阶段二-视觉评估基础：固定游戏相机下记录候选端点世界锚点、屏幕投影和视图深度，并输出 accepted/rejected 诊断。
- [x] 阶段二-Gizmo 基础：Level View 按 pending/accepted/rejected 状态绘制候选连接箭头。
- [x] 阶段三-有效 Graph 基础：按 accepted 候选生成有向邻接、双向边和 `topologyVersion`。

- [x] Part 内局部固定连接基础：已从锚点距离启发式切换为面顶点、同向法线、共面、正长度边重合和基础几何检查。
- [x] 刷新入口基础：Part 变换、Pivot、Yaw、Scale、行为修改和 Part 编辑返回后统一重建 PathRuntime。
- [x] 通行语义基础：使用节点类型和附着面几何参与连接评估，不再依赖节点方向字段。
- [x] 编辑器 UI 配置基础：Level Inspector 提供 PathNode 全局选择、跨 Part 候选起点/终点、方向选择、添加和删除；不要求用户编辑 JSON。
- [x] 候选配置 UX 改造基础：支持“拾取起点/终点”模式，在 Level View 直接点击节点；候选列表显示端点和评估状态，删除不要求记忆候选 ID。
- [x] Level Gizmo 交互基础：节点球体支持鼠标拾取；仅在拾取模式下悬停高亮，普通 Level View 不因鼠标移动变色；候选列表选中时对应连线加粗。- [x] Level Gizmo 显示局部固定边：Level View 绘制所有 `local_fixed` 边，使用无箭头普通连线；跨 Part 候选仍使用状态箭头。
- [x] PathNode 稳定化精简：移除 YAGNI 的 `entryDirection`、`exitDirection`、`orientation`，保留 `id`、Cell、Face、`kind`、`walkable` 核心字段。
- [x] 稳定版路径评估回归基础：运行时不再读取上述 YAGNI 字段；默认关卡可正常加载并构建 Graph。
- [ ] 稳定版路径评估回归：基于精简 PathNode 重新验证 Part 内面邻接和跨 Part 面投影。每完成一个可独立验收的步骤，先更新本节勾选状态和对应说明；实现完成后由用户进行预览和交互验证。收到用户验证结果后，再在后续会话中复核变更、提交并推送；中间缺失模块属于计划内未完成项，不得据此改变已确认的职责边界。

## 用户协作规范

- 每个独立步骤完成后，先在本计划中标记已完成内容。
- 实现完成后先交给用户验证，不把自动构建、LSP 或独立 Runtime 检查当作用户预览验收的替代。
- 用户反馈“验证通过”或提供具体问题后，再进行代码复核、提交并推送；不要在用户验证前自动提交本步骤。
- 提交前必须说明当前完成范围、尚未完成范围和已知验证结果。
- 中间状态缺少的模块不代表架构偏移；应依据本计划和验收标准继续推进，不因局部未完成而临时改变真相源或职责边界。
- 未经验证的替代方案不得升级为目标架构；发现问题时先区分代码错误、资源缺失、验证环境错误和计划内未完成。

路径数据和 Preview 存储边界遵守：

```text
docs/level-storage-and-source-of-truth.md
```

在 Runtime 实际存档路径未被诊断确认前，不得把 `/workspace/levels` 或 `/workspace/parts` 的统计当作 Preview 当前关卡统计。
## 用户编辑能力约束

用户当前没有直接读写或编辑 JSON 的能力，也没有其他直接修改游戏内容的途径。所有关卡、Part、PathNode、候选连接和测试配置，必须通过游戏内的 `EditorUI`、`LevelEditorUI`、`VoxelSandbox` 及相关 UI 间接完成。

因此：

- 不得把手工修改 `levels/*.json` 或 `parts/*.json` 作为用户测试步骤；
- 任何需要用户配置的数据都必须提供对应 Editor UI；
- UI 必须调用数据模型/编辑器服务，不能自己维护第二份路径状态；
- 保存、加载和刷新由编辑器代码负责；
- 如果某项功能暂时只能通过 JSON 配置，必须视为工具链缺口，不能视为用户可用功能。

路径系统的完成标准不仅是运行时 Graph 正确，还必须满足：

```text
用户只通过游戏 Editor UI
  -> 创建和编辑 PathNode
  -> 创建和编辑跨 Part 候选
  -> 调整 Part / 机关状态
  -> 观察节点、候选边、有效边和诊断
  -> 保存关卡
```


当前提交包含用于闭合运行时链路的**不稳定原型实现**，尤其是：

- 同一 Part 内局部固定连接仍使用“局部锚点距离 + 法向”的临时启发式；
- 该规则尚未替换为三棱柱体素的 Cell/Face 面邻接语义；
- 视觉连接目前仍是端点投影、深度和基础方向的最小评估；
- Snap 动画和 `SnapCompleted` 原子拓扑提交尚未完成。

本版本用于保存当前研究和验证进度，不代表最终路径判定规则。后续必须以三棱柱 Cell/Face 的离散邻接规则替换距离阈值，不能继续扩大该启发式的使用范围。



- 角色完整动画；
- BFS 的具体实现细节；
- 通用 NavMesh；
- 任意几何体的无约束自动连边；
- 成品级美术 Gizmo；
- 独立 Camera Mode 或拍照模式。

路径节点系统的完成标准是：**设计者可以在可走面上配置节点，看到固定相机下的视觉连接评估，并在运行时得到可复现的当前有效 Path Graph。**
