# 路径节点与 Gizmo 三阶段开发计划

## 计划定位

本计划服务于“六边形纪念碑谷”错视解谜玩法，不把路径节点做成普通 NavMesh 点，也不把 Gizmo 做成脱离玩法的通用编辑器装饰。

目标工作流是：

```text
可走面节点
  -> 归属 Part / 机关
  -> 固定游戏相机下视觉连接评估
  -> 生成当前有效 Path Graph
  -> Debug 显示
  -> 后续寻路和角色移动消费 Graph
```

公开资料没有披露纪念碑谷内部 Gizmo 的具体颜色、图标或交互界面，因此本计划只采用已确认的成熟原则：

- 节点布置在可走空间上；
- 节点可表达可达 / 不可达状态；
- 节点支持不同通行语义；
- 几何体到达合法 Snap 状态后重新评估连接；
- 评估使用固定游戏相机的投影、深度和遮挡关系；
- 编辑器 Gizmo 必须帮助设计者理解节点、连接和评估结果。

## 阶段一：建立可走面路径节点与基础 Gizmo

### 目标

建立路径节点的数据真相源，并让节点稳定地显示在对应三棱柱的可走面上。

### 数据范围

每个路径节点至少包含：

```lua
{
    id = "start_01",
    partId = "part_static_base",
    voxelCellKey = "0:0:0:0",
    face = "top",
    kind = "floor",
    walkable = true,
    orientation = 0,
    entryDirection = "forward",
    exitDirection = "forward",
}
```

必须区分：

- 体素归属；
- 面归属；
- 面类型和通行语义；
- 入口 / 出口方向；
- 节点 ID；
- 所属 Part 和可变机关。

路径节点的几何锚点默认放在**可走面的中心或面内设计锚点**，不放在体素中心、边中心或顶点。锚点位置应由面几何和局部三棱柱 Grid 派生，不能让任意浮点 Scene Node 成为逻辑真相。

### Gizmo 内容

基础 Gizmo 只显示节点本体和方向，不提前绘制未经评估的路径：

- 节点中心标记：显示在可走面上方的微小 3D 标记；
- 面法向箭头：表示站立面朝向；
- 入口 / 出口方向：使用不同方向标记；
- 节点 ID 标签：用于定位和 Debug；
- 节点状态：至少区分未验证、有效、不可用；
- 选中节点：显示所属体素、面、Part 和机关信息。

颜色和图标属于项目 Gizmo 规范，不声称是纪念碑谷官方颜色。推荐：

```text
白 / 蓝：已配置节点
绿：当前可达或评估有效
黄：候选 / 待评估
红：评估失败或不可用
紫：视觉对象到逻辑节点的映射标记
```

### 阶段验收

- 可在指定三棱柱可走面上创建、选择和删除节点；
- 节点不会错误落在体素中心、边或顶点；
- 节点拥有稳定 ID 和面语义；
- 节点移动 Part 或旋转机关后，显示位置由当前 Transform 正确派生；
- 不依赖模型碰撞生成节点；
- 关闭体素显示后，节点 Gizmo 仍可独立显示。

## 阶段二：建立路径节点 Gizmo 与视觉连接评估

### 目标

让 Gizmo 表达纪念碑谷式 Path Graph 的核心状态：哪些节点可能连接、哪些连接有效、为什么连接被拒绝。

### 关卡配置

设计者配置：

- 可走面节点；
- 节点的面类型、方向和通行语义；
- 节点所属 Part 与机关；
- 机关允许的离散 Snap 状态；
- 节点连接候选范围和视觉评估规则；
- 必要的固定连接或明确覆盖。

设计者不为每个机关状态手写全部错视连接。错视连接由运行时在合法 Snap 状态下评估生成。

### 视觉连接评估

对配置范围内的候选节点对，使用固定游戏相机检查：

- 两个可走面的屏幕投影边界是否连续或在容差内对齐；
- 入口 / 出口方向是否兼容；
- 面法向和行走方向是否满足通行语义；
- 节点和边界的相机深度顺序；
- 中间遮挡是否破坏视觉连接；
- 当前机关是否已经到达合法 Snap 状态。

评估结果生成当前有效 Path Graph。显式边只能用于固定连接、临时白盒兜底、设计者覆盖或 Debug 对照。

### Gizmo 内容

Gizmo 必须区分三种连接状态：

```text
候选连接：灰 / 黄虚线，显示“待评估”或候选原因
有效连接：绿实线，显示当前可走方向
拒绝连接：红虚线，显示拒绝原因
```

连接 Gizmo 还应支持：

- 单向 / 双向箭头；
- 连接两端节点 ID；
- 评估失败原因；
- 屏幕投影边界或对应边标记；
- 相机深度值或深度排序序号；
- 当前机关 Snap 状态；
- 当前拓扑版本号。

旋转动画中不重新提交 Graph。机关到达 Snap 状态后：

```text
提交离散机关状态
  -> 重建视觉连接评估
  -> 原子替换当前有效 Graph
  -> 刷新连接 Gizmo
```

### 阶段验收

- 旋转机关处于初始状态时，目标连接显示为拒绝或未激活；
- 机关到达视觉邻接的合法 Snap 状态后，连接自动变为有效；
- 连接 Gizmo 能解释“为什么有效 / 为什么拒绝”；
- 编辑器自由相机变化不会改变游戏 Graph；
- 只使用固定游戏相机进行视觉连接评估；
- 不使用模型距离、物理碰撞或 Scene 树自动创建连接。

## 阶段三：接入运行时 Path Graph 与独立 Debug 工作流

### 目标

将路径节点和视觉评估结果接入运行时，形成可独立验证、可复现、可供寻路消费的当前有效 Path Graph。

### 运行时流程

```text
关卡配置
  -> 可走面节点
  -> Part / 机关当前状态
  -> 固定游戏相机视觉连接评估
  -> 当前有效 Path Graph
  -> 可达区域
  -> 后续 BFS / 角色移动
```

Graph 是运行时寻路的输入，但寻路不能反向定义 Graph。Graph 与渲染模型、体素节点、物理碰撞保持分离。

### 运行时状态

必须记录：

- 当前节点集合；
- 当前有效连接集合；
- 候选和拒绝连接及原因；
- 当前机关 Snap 状态；
- `topologyVersion`；
- 评估使用的固定游戏相机配置；
- 视觉对象与 `logicalNodeId` 的映射。

### Debug 显示

运行时 Gizmo / Debug 层至少支持：

- 节点中心和面法向；
- 节点 ID、Part ID、Cell Key；
- 当前有效连接；
- 当前关闭或拒绝连接；
- 连接评估原因；
- 当前可达区域；
- 点击视觉对象后的逻辑节点映射；
- 当前机关状态和拓扑版本；
- 后续 BFS 输出的 nodeId 路径预览。

运行时 Debug 必须能回答：

```text
这个视觉对象对应哪个路径节点？
节点属于哪个可走面？
当前机关处于哪个 Snap 状态？
这两个面为什么连上或没有连上？
当前 Graph 有哪些有效边？
目标节点当前是否可达？
```

### 阶段验收

- 关闭体素表现后，逻辑节点、连接和可达区域仍可显示；
- 替换体素模型不会改变节点 ID 和 Graph 结果；
- 机关状态从一个 Snap 状态切换到另一个状态时，Graph 原子刷新；
- 旋转动画中不存在半状态 Graph；
- Graph 可保存或打印为稳定的调试数据；
- 后续 BFS 可以直接消费当前有效 Graph，不需要修改节点系统。

## 计划边界

本计划严格只有三个阶段。以下内容不在路径节点 Gizmo 的本轮范围内：

- 角色完整动画；
- BFS 的具体实现细节；
- 通用 NavMesh；
- 任意几何体的无约束自动连边；
- 成品级美术 Gizmo；
- 独立 Camera Mode 或拍照模式。

路径节点系统的完成标准是：**设计者可以在可走面上配置节点，看到固定相机下的视觉连接评估，并在运行时得到可复现的当前有效 Path Graph。**
